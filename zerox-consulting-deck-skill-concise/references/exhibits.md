# 证据与表达：从输入结构到实现

**什么时候读**：S1 只需标记手上的材料能构成哪些输入结构；S3 构思出页面关系之后、S4 实现阶段正式读这一份做选型与写页。

**读完要能做什么**：把原始数据或文本识别成输入结构 → 说清读者要完成的动作 → 选定实现路径 → 知道这条路径的容量边界与放不下时该改什么。整页关系怎么展开读[整页创作](page_design.md)；S3 选型读[图表选型](charts.md)；共享几何与复杂标注读[精度与标注](precision.md)。

选型路由固定为：

`输入结构 → 可比性检查 → 读者要完成的动作 → 整页视觉构思／按需选型 → 实现与容量适配`

先按整页创作确定关系怎样在画布上展开。下面的输入索引和实现路径服务构思，**不以组件种类决定页面结构**。

## 一、先识别输入结构，再定读者的动作

不要直接把一批文件"摘要后画图"。先把能进入同一视觉编码的数据整理成输入结构；一页可以使用多个互补结构。

| 输入结构 | 最少字段／关系 | 读者要完成的动作 | 不满足时怎么办 |
|---|---|---|---|
| 对象×指标明细 | 对象、指标、值、单位、期间、范围 | 查值、排名、看差距、看构成 | 单位或期间不同则分组表，不共用量尺 |
| 时间序列 | 时间、系列、值、单位、事实／预测 | 看趋势、解释起止变化 | 时间口径断裂则分段，不连线 |
| 两期／两组配对 | 对象、起点、终点、同一量尺 | 看差距、看排名迁移 | 对象无法配对则用两个排序表 |
| 部分—整体 | 类别、分项、值、明确分母 | 看构成、同看总量与构成 | 分母不同或未知则禁止画成 100% |
| 起止与贡献项 | 起点、终点、贡献项、闭合规则 | 解释起止变化 | 不闭合时显式列出缺口，不编一个"其他" |
| 原始观测／样本 | 每条观测、分组、测量值 | 看分布与不确定性 | 只有均值时不能伪造分布 |
| 两变量×规模 | 对象、x、y，可选规模及同口径 | 看相关与定位 | 两轴定性时用矩阵；规模单位不同不画气泡 |
| 行×列矩阵 | 行对象、列维度、值或定义过的档级 | 扫模式、多标准评估 | 精确查数优先表；档级无定义则先补定义 |
| 节点—边—流量 | 节点标识、边、方向、可选权重 | 看流向与转化 | 无真实边时不用网络图 |
| 层级／拆解 | 父子关系、同层拆分逻辑 | 看层级与驱动 | 同层逻辑混杂时先重构分类 |
| 任务—责任—时间 | 任务、责任人、阶段／日期、依赖、交付／门禁 | 看过程与责任 | 没有日期时用阶段，不伪造甘特长度 |
| 地理记录 | 地区编码／经纬度、指标、时间 | 看空间分布与流向 | 地理位置不影响判断时改排序条形 |
| 编码后的文本证据 | 文本片段、主题码、对象、来源定位 | 比较案例、看证据强弱 | 未系统编码时不能把摘录数量画成占比 |
| 长文本论证材料 | 主张、证据、反证／边界、来源 | 验证机制 | 没有共同维度时保留结构化文字 |
| 方案×标准 | 方案、标准、权重／定义、事实依据 | 做条件化决策、多标准评估 | 权重和评分锚点不透明时不算总分 |

同一份数据可以服务不同判断。候选范围、取舍与适用条件统一见[图表选型](charts.md)，不以现成组件决定页面结构。

## 二、文本材料的转换规则

文本先结构化，再决定是否图示化。

| 文本中反复出现的结构 | 应抽取成 | 禁止的捷径 |
|---|---|---|
| 多家公司或地区反复出现同类事实 | 对象×共同维度 | 每家公司做一张独立卡片后声称可比 |
| "因为—所以—导致"语句 | 主体、动作、边、证据、替代解释 | 把语言中的因果词直接画成已证实箭头 |
| 责任、动作、交付、条件 | 任务—角色—阶段—门禁 | 只有时间顺序却画复杂网络 |
| 方案、优缺点、限制 | 方案×共同标准 | 三列各写不同维度的长段落 |
| 高频主题或观点 | 主题码×对象×来源 | 未定义编码过程就给"占比" |
| 主张、支持材料、反证、缺口 | 主张—证据—边界 | 用图标代替来源或证据强度 |
| 分类、子类、例子 | 父子层级 | 非穷尽分类画成完整层级 |
| 不同材料没有共同维度 | 独立证据组 | 为了"有图"强行做雷达、流程或 2×2 |

引文只保留能证明当前判断的最短片段，并保留来源定位。文本计数只有在语料范围、编码规则、重复处理和分母明确时才可进入统计图。

## 三、高密度页面的组合与容量预算

优先让多个展品共同完成一个证明责任，而不是把每张图孤立成一页。

| 页面组合 | 适用关系 | 失败信号 |
|---|---|---|
| 主比较＋驱动验证 | 先证明差距，再解释来源 | 下半模块重复上图数字 |
| 总量＋构成 | 同时回答规模与结构 | 两图没有共同对象或期间 |
| 分布＋代表案例 | 定量模式需要定性解释 | 案例被当成总体证明 |
| 机制＋证据／反例 | 因果仍需验证 | 边没有证据状态或验证指标 |
| 概览＋小倍数 | 总体模式与分组差异 | 各分面量尺不同仍并排比较 |
| 表格＋微型图 | 精确查值同时需要模式扫描 | 每列使用不同且无说明的色阶 |
| 决策表＋门禁 | 方案选择需绑定后续条件 | 推荐项没有成立条件和退出条件 |

### 起始容量预算

以下是 1280×720 reading 的**起始预算，不是普遍定律**，可以按实际媒介调整：

排序条形正文通常 8–15 项、附录最多约 24 项；折线正文通常不超过 5 条线；热力正文通常不超过约 120–160 格且单元格文字仍需可读；散点超过 15 个点不默认全标签，只标关键点；表格不设固定 10 行×7 列上限，先保证列单位、可比较维度和可读的数据文字（通常建议 15–16px），超页后按逻辑分组分页；树／网络一页看不清关系时输出总览＋局部，而不是整体缩小。**超出以上任一项时分页、分面、换更宽的版位或换绘制路径，不能改成表格。**

## 四、实现路径

| 路径 | 适合 | 选择理由 |
|---|---|---|
| `echarts-recipe` | 高频定量图 | 有统一数据契约、输入校验、主题、标签与 SSR 路径 |
| `echarts-native` | ECharts 已有但尚未封装的统计／关系图 | 数据结构清晰，原生能力成熟 |
| `echarts-custom` | 坐标系内的专用几何，如区间、复杂甘特、成本曲线 | 仍需要轴、缩放、图例与数据映射 |
| `exhibit-kit` | 构建期静态咨询展品，如瀑布、哑铃、Mekko | 打印稳定，含咨询特定校验与引线标注通道 |
| `html-css` | 精确表格与高文本密度结构，如 RACI、证据矩阵 | 文字换行、列宽和分页更可控 |
| `svg-layout` | 战略屋、价值链、鱼骨等语义图 | 几何和关系高度专用，按页面生成并目视验收 |
| `elk-layout` | 复杂有向依赖图 | 只有真实复杂网络才值得自动布线 |

**ECharts 能画不等于必须使用。** 表格、流程和文本型关系图如果转成 ECharts 后会降低文字控制或增加运行时依赖，应保留 HTML／SVG。

`assets/deck-forms.js` 只登记实现入口及容量，不是允许图型的全集。已有入口可用 `sweep_forms.cjs` 查找；其他原生 ECharts、组合或手写 SVG 统一用 `svg.custom`，在 `pages.json` 用 `visual` 写实际图型并对应成稿 `data-visual`。选择先服从内容，再决定复用或自定义；自定义仍须核对数据映射并实际看图。

## 五、已有 API

### EChartsRecipes 与 ChartRuntime

`assets/echarts-recipes.js` 负责输入校验与 option；`assets/chart-runtime.js` 统一画布预算、主题字体、文字对比度与实测文字验收，浏览器与 SSR 共用这一层。**预算只给风险提示，验收只报问题，两者都不改变作者选定的表达。**

配方调用固定为 `prepare → setOption → check`。**只调用 `build` 或 `prepare` 不算最终验收。** `check` 读取实际文字包围盒，返回 `{status, problems}`：`problems` 逐条给出类型（`bounds`／`overlap`／`font`／`missing`）、涉及的文字和该改什么，`status` 不是 `ok` 就必须返修。`missing` 指声明的类目或期间没有出现在图上——**坐标轴标签被自动抽稀、截断或隐藏，和文字互相遮挡一样阻止通过**。`prepare` 的 `risks` 是类别数、标签空间、层级深度这类经验提示，用来提前改布局，不是失败判据；引擎里它写在图元的 `data-chart-risks` 上，QA 汇总为提示。`check` 不覆盖形状遮挡、语义或美学问题。

```html
<div class="chart" data-recipe="rankedBar" data-spec='{"items":[{"label":"甲","value":42}],"unit":"亿元"}'></div>
```

| 配方 | 输入结构 | 起始边界 |
|---|---|---|
| rankedBar | items:[{label,value,display?,role?,selected?}] | 排名／差距；最多 24 项，正文宜更少 |
| groupedBar | categories + series:[{name,values}] | 并列比较；最多 12 类×4 系列 |
| timeSeries | periods + series:[{name,values}] | 趋势；最多 36 期×5 系列，更多时分面 |
| composition | items:[{label,segments}], mode | 普通／100% 堆积；最多 12 类×6 系列 |
| histogram | bins:[{label,value}] | 已正确分箱的分布；不从均值伪造 |
| scatter | items:[{label,x,y,size?,selected?}], xMin/xMax/yMin/yMax?, xLabel/yLabel/xUnit/yUnit? | 散点／气泡；超过 15 点只标关键点。两轴默认**含零但不越过零**（全正的数据轴从 0 起，不会画出一条负值轴）；要收窄用 `xMin`／`xMax`／`yMin`／`yMax`，**可以收窄但不能把数据切掉**，切了当场报错。纵轴名字过长时自动折行，不必自己把名字压短、或把单位挪出坐标轴 |
| heatmap | rows + columns + values | 连续有限数值矩阵；最多 160 格，不接受 null；未观察／缺失用自定义 SVG 或 HTML 单独编码 |
| sankey | nodes + links:[{source,target,value}] | 真实流量；最多 30 节点／60 边 |
| tree | root:{label,value?,children} | 层级；最多 48 节点 |

这些是**底层拒绝阈值**，不是"该数量一定放得下"的保证，也不是数据分析的上限。超过阈值先由作者分组，阈值内仍要按真实尺寸验收。**不能通过巨大 viewBox 缩小整张图来绕过。**

零值与极小值不能省略，也不能虚增图元：气泡面积严格正比于规模，零规模用等大的空心位置标记表示位置并写明 0，缺失规模不当作 0；构成中的小片、零值与窄列改走同侧引线通道，面积仍按原值计算，总量级另有位置标记；桑基要求无环、节点有效、中间流量闭合，零流量连线只能画成无宽度并须在旁解读里写明；热力按实际连续色阶选择至少 4.5:1 的文字反差；趋势零基线包含负值，不把负值裁掉。**这些情况都不转成表格。**

构建期静态 SVG：

```bash
node scripts/render_echarts_svg.cjs input.json chart.svg
```

输入包含 `recipe`、`spec`、`width`、`height`、`theme_id`，可设 `fontSize`（至少 14）；示例见 `assets/echarts-recipe-example.json`。脚本固定依赖版本并关闭动画与 tooltip；一张图对应一个 SVG 文件，不覆盖已有同名文件。**实测文字验收不通过时直接失败并打印涉及的文字和该改什么**，不产出任何替代文件；需要第二张图时由作者另拆一个模块渲染。也可传原生 `option`，但没有配方的输入语义校验。SSR 通过 fontkit 加载固定字体并启用 tnum 测宽，浏览器在 `window.deckReady` 后以同字体、同特性测量；**输出 SVG 仍依赖字体，必须内联到同配置且已打包字体的 HTML，不能独立冒称字体自包含。**

数据图元可按阅读任务使用透明叠加或连续色阶；网格、参考线和普通辅助底纹优先主题实色。PDF 栅格与文字检查共用同一 Canvas 提供者，仍须查看实际输出中的叠加色、标签与尺度；装饰性色条禁令不因使用透明度而改变。

可复现案例：`node scripts/test_dense_inputs.cjs`、`node scripts/build_dense_reference.cjs output-dir --theme=mckinsey` 与随后的 `qa_deck.cjs`（只读固定合成夹具）。**它不是通用 CSV／Excel／PDF 解析器，不自动完成调研、文本编码和语义选图。**

### ExhibitKit

零依赖，可构建期生成静态 SVG。

```js
const kit = require('./assets/exhibit-kit.js');
const svg = kit.waterfall({width:740,height:330,items:[
 {label:'期初',type:'total',value:11.2},{label:'电商',type:'delta',value:0.4},{label:'期末',type:'total',value:10.4}]});
```

共同参数：`width`／`height`／`fontSize`（至少 14）、`palette = DeckThemes.palette(theme_id)`。组件无第三方绘图库依赖，但需要本技能的统一字体配置；HTML 比较表继承所在报告样式。数据与 SVG 绑定，**不写死坐标伪装测量**；库拒绝非有限值与结构错误，但某些定性字段仍要作者验证。源数据证据由页面 Source 承载，不由组件虚构；SVG 内文字必须转义。

| 函数 | 专用数据字段 |
|---|---|
| waterfall | items:[{label,type:'total'/'delta'/'subtotal',value}] |
| dumbbell / slope | items:[{label,start,end}], startLabel, endLabel | 哑铃的两个数值标签会随行距自适应：行距宽裕时放点的上／下方，行距紧时改为水平贴点，避免相邻两行的数字叠在同一列上 |
| bullet | items:[{label,value,target,max,ranges:[递增阈值]}] |
| heatmap | rows:[标签], columns:[标签], values:[[数值]] |
| mekko / stacked | items:[{label,segments:[{label,value}]}]；stacked 另有 mode |
| comparisonTable | columns:[{key,label,type,unit,format,bar,derive}], rows:[{kind,values}]；输出 HTML |
| processFlow | stages:[{label,owner,output,gate}], transitions:[相邻转换条件] |
| tree | root:{label,children:[递归节点]} |
| swimlane | lanes:[标签], stages:[标签], items:[{id,label,lane,stage}], edges:[{from,to}] | 连线**只支持相邻阶段**：跨阶段的水平段会从中间那些节点框上穿过去，画出来读不出关系，所以当场拒绝并提示拆成逐段 |

另有 `formatNumber(value,{decimals,grouping,signed,suffix})` 与 `difference(start,end,{mode,decimals,suffix,basis,periods})`：`mode` 为 absolute（默认）／relative／pp／cagr，pp 必填 `basis`（fraction 或 percent），cagr 必填实际年数 `periods`，常规 relative 不接受零或负起点，cagr 不接受非正起止值。**这两个函数只格式化显示，不修改几何源值。**

### 旁解读：锚点契约与标注层

图上的"旁解读"（差额、增长率、份额、极值、缺口）由 `assets/annotation-layer.js` 统一完成，**摆位逻辑不区分图型**：只要 SVG 里有锚点，哑铃、Mekko、子弹、瀑布、热力、`precision.*`、`recipe.*` 乃至自绘 SVG 走的是同一套候选、碰撞避让与引线路由，**不要为某一类图另写一套标签摆位**。

区分在**准入**而不在摆位：`annotation:'layer'` 的形式由通用层自动摆位，`pages.json` 里直接写 `annotations` 即可；其余形式要写旁解读，须同时声明 `annotationMode:"manual"`，由作者负责摆位并承担目视验收。**这不限制你能画什么**——旁解读是每页都要争取的东西，不该反过来把它变成"只有某几种图能用"的约束。

**锚点契约。** 每个数据图元在生成时就带上可核对的锚点，只读显式声明，不从几何反推：

```html
<rect data-anchor-id="seg:南区|新业务" data-anchor-x="412" data-anchor-y="188"
      data-anchor-side="right" data-anchor-box="380,150,64,38" data-value="70"/>
```

- `data-anchor-x/y` 是图元**参考点**（通常是中心），`data-anchor-box` 必须等于图元**真实几何包围盒**（不含描边），`data-anchor-side` 是首选出引线方向。
- 引线接在 `box` 的边界上，**不从中心穿出来**；标注框贴在边界外侧，装不下就沿候选环后退。
- 各函数的锚点 id：`dumbbell`/`slope` 用 `start:类别`／`end:类别`；`bullet` 用 `value:类别`／`target:类别`；`waterfall` 用 `bar:类别`；`mekko`/`stacked` 用 `seg:列|系列`；`heatmap` 用 `cell:行|列`。`AnnotationLayer.collect(svg)` 可从任意已生成 SVG（含自绘或 ECharts 产物）取回锚点。
- 九种配方（`recipe.*`）同样带锚点，id 与 kit 同风格：`rankedBar` 用 `bar:类别`（类别取排序后的名字）；`groupedBar` 用 `bar:类别|系列`；`timeSeries` 用 `point:期间|系列`；`composition` 用 `seg:列|系列`；`histogram` 用 `bin:箱`；`scatter` 用 `point:标签`；`heatmap` 用 `cell:行|列`；`sankey` 用 `node:名称`／`flow:源→目标`；`tree` 用 `node:标签`。**配方页写 `annotations` 的方式与 kit 页完全一样**（`render({recipe,spec,annotations})`），锚点由渲染期从真实图元几何生成，不需要另写一套。
- **旁解读只出现在成稿。** 锚点的身份通道（`ecmeta_*`）只在 SSR 渲染时写入，`render_echarts_svg.cjs` 出的内联 SVG 才有；`deck_engine.html` 里的实时预览跑的是非 SSR 渲染，那棵 DOM 里没有锚点也没有旁解读。看预览时不要据此判断标注丢了，以成稿为准。
- 配方的几处边界：**`scatter` 的两轴范围由 `xMin/xMax/yMin/yMax` 控制，默认含零但不越过零**——以前运行时无条件把轴写成"含零再向两侧留 12% 空白"，全为正的营收会得到一条到 −49 的横轴，作者给的 min/max 也被静默覆写；现在全正的轴从 0 起、全负的到 0 止，跨零的照常两侧留白，显式范围优先且必须覆盖全部取值。`scatter` 的锚点原值只有一个字段，取**纵轴值**，横轴与规模留在标签里；`rankedBar` 的基准线画成 `ec-line`，不是数据图元，因此没有锚点，要标注"高于／低于基准"请落在柱子上；`timeSeries` 期间数超过 8 时默认不画数据点，**没有点就没有锚点**，需要标注就显式给 `showSymbol:true`（否则渲染会直接报错并点出这根杠杆）。纵轴范围用 `min`／`max` 收窄、用 `zeroBaseline` 强制含零，两者都生效且**必须覆盖全部取值**，切掉数据会当场报错；锚点 id 里的期号取自 `periods` 原文，写进 `annotations` 时少写或多写空白都还能对上，改写期号本身则会报错并列出本图可用的锚点。

**已经踩过的坑（改这条链路前先读）。** 下面四个缺陷**都通过了生成期的自查**，只有"独立读取真实渲染结果"才暴露出来；它们的共同点是**声明与真实对象用了两套约定**。

| 症状 | 为什么当时看不见 | 规则 |
|---|---|---|
| 标注整段压在别的文字上，引线接到空处 | 内部 audit 用的是引擎自己算的框，而绘制原点用了另一套约定，两边都"自洽" | 框一律以**左缘**起算；`text-anchor` 只是绘制原点——`start` 用左缘、`middle` 用中心、`end` 用右缘——**只在序列化那一处换算**，其他代码不许再算一遍 |
| 锚点声明框与图元真实包围盒对不上 | 生成期只看自己的 `box` 字段，从不与真实对象对照 | `data-anchor-box` 必须**等于图元真实几何包围盒**：不含描边、阴影和渐变。为"视觉厚度"把描边算进声明，就是让声明开始说谎 |
| 同上，换成引擎后整批偏差 | 两次都"自洽"：一次是 zrender 的 `getBoundingRect()` 把描边算了进去（有填充按 `lineWidth` 外扩半宽，无填充还会按 `strokeContainThreshold` 再放大），一次是核对时错拿了 `getBBox()` | 声明框取**纯几何**：zrender 在同一个调用里把不含描边的框留在 `_rect` 上，取它；并且声明框是**根坐标**——`getBBox()` 给的是元素**自己坐标系**里的框，既不含元素自身的 `transform`，也不含祖先 `<g>` 的位移，核对时必须经 `getCTM()`／`getScreenCTM()` 换算到 viewBox 空间再比 |
| 从成稿 SVG 读回锚点时拿不到原值，自动旁注一条也提不出来 | 写入端只序列化了一部分字段，读取端却假设值在 `data-value` 上 | 锚点契约必须**自足**：`collect()` 只能依赖 `data-anchor-*`，不许假设图元上恰好还有别的属性；**写什么读什么要能往返**，并为往返写测试 |
| 某个语义分支不做模板替换，`{delta}` 原样印在图上 | 产生文字的地方各写了一遍解析 | 产生文字**只有一个入口**；新增 kind 走同一个解析器，不另开分支 |

**独立核对是这四条唯一的共同防线**：`test_annotation_browser.cjs` 不消费渲染器的 geometry/audit，而是从真实 DOM 重新推导——声明框必须等于真实 `getBBox()`，引线两端必须落在真实边界上。**改动这条链路后，只跑生成期自检不算验证。**

**标注 spec。** 把 `annotations` 交给同一个 spec，标注由原值派生，位置由引擎决定：

```js
kit.dumbbell({width:620,height:330,items:[{label:'商超',start:6.4,end:5.3},{label:'电商',start:1.6,end:2.0}],
  annotations:[
    {on:'end:商超',kind:'delta',from:'start:商超',text:'{label} {delta}（{rate}）',weight:600},
    {on:'end:电商',kind:'rate', from:'start:电商'},
    {on:'seg:南区|新业务',kind:'share',text:'{label} 占该区 {value}'},
    {on:'bar:商超',kind:'delta',text:'主要拖累 {value}'},
    {on:'value:交付达成率%',kind:'delta',from:'target:交付达成率%',text:'缺口 {delta}'},
    {on:'cell:北区|Q4',kind:'note',text:'最高 {value}，需核实口径'}
  ]});
```

| 字段 | 取值 | 说明 |
|---|---|---|
| `kind` | value／delta／rate／pp／multiple／share／rank／note | 决定数值语义与格式；`delta` 等**不写 `from` 时按本锚点原值**格式化（瀑布 delta 柱即此用法） |
| `from`／`to` | 锚点 id | 差额、增长率、倍数、区间标注的两个真实端点 |
| `of` | 锚点 id | 份额分母；省略时按同 `group` 锚点求和，**分母不明就不给份额** |
| `text` | 模板 | `{label}` `{value}` 任何标注都能用；`{delta}` `{rate}` `{start}` `{end}` 要比较两个端点，**只有写了 `from` 才有值**。没写 `from` 却用了它，会当场报错说明缺什么——不会把 `{delta}` 原样印在图上。不写 `text` 则只输出数值 |
| `side`／`weight`／`color`／`place` | — | 覆盖默认朝向、字重、颜色与候选参数 |

**容量与失败。** 标注装不下时组件**自动向右／向下扩容**（图元坐标不动，与原引擎 `fit:'grow'` 同一约定），SVG 上的 `data-requested-size`／`data-actual-size` 回传真实尺寸，宿主必须按实际尺寸排版。扩容仍装不下就**报错并列出候选被拒的原因计数**——那是改规格的信号：加空间、减标注、换分面，不是删掉关键解读，也不是缩小 viewBox。

**自动旁注候选。** 拿不准该标什么时先跑 `node scripts/propose_annotations.cjs spec.json`：它渲染一次展品、读回锚点，按**配对变化量、实际与目标的缺口、同组极值、领先差距、份额、离群**给出候选，每条都附写法（怎么算的）和引用（用了哪些锚点）。**候选只是建议**——采纳哪些写进 `pages.json` 的 `annotations`，口径与可比性仍由作者核对；标注层只负责放得下、不压图、不丢标签。

**验收。** `node scripts/test_annotation_layer.cjs` 校验锚点契约、语义、碰撞回退与候选规则；`node scripts/test_annotation_browser.cjs` 在真实浏览器里独立核对**声明框是否等于真实 bbox、引线两端是否绑在真实边界上**，并用 4px 突变反例证明检查器有效；`node scripts/build_annotation_example.cjs [输出目录]` 生成可目视的样张。**自动几何通过不代替实际看图。**

### 参数边界

| 对象 | 边界 |
|---|---|
| 画布与字号 | `width` 默认 960、`height` 默认 500（最低 320×200），`fontSize` 默认 14。参数是 **SVG 内部逻辑像素**，嵌入容器缩小后要重测有效字号，不能用巨大 viewBox 偷缩字 |
| domain | 默认由数据生成且包含 0，等值时扩张。**自定义范围不能截断数据；跨页热力比较必须固定同一 domain**（例如评分 [1,5]） |
| waterfall | 起点 total 可设基线，后续 total 必须等于累计；subtotal 可省 value，传入则须闭合 |
| bullet | `max` 必填且大于 0，value／target 在 [0,max] 内；`ranges` 须递增且在范围内。**分档必须另外标注业务定义，组件不自动发明合格阈值** |
| swimlane | lane／stage 为 0 起整数，id 唯一且必填，同一单元格仅 1 个节点；edges 只能引用已有 id。复杂分支与反馈仍需专门路径规划 |
| label | 必须非空可见；长标签由作者换行或缩短，**组件不自动完成复杂标签避让** |
| Mekko／stacked | 小片、零值和放不下类目名的窄列自动改走同一侧的引线通道：面积与列宽仍按原值计算，零值只留位置标记并写明 0；通道排不下或剩余绘图区过窄时直接报错，**不改表**。已取消 `labels:'table'` 开关 |
| comparisonTable | `bar.role` 取 `value` 或 `delta` 显式指定色义：delta 用数学正负色，value 用强调色，**不能把品牌绿当作增长色**。缺失值显示"—"，总计显式给定、不擅自汇总比率；非法增长基数报错，需改用绝对差或文字说明。表格高度由内容决定，需自行分页 |
| processFlow | 至少 2 阶段、转换条件数等于阶段数减 1，stages 必填 label／owner／output／gate。**分支、反馈或跨职能关系用其他图型** |
| 验证范围 | 只有数值与已覆盖的结构字段经过脚本验证，**任意调色、尺寸和数据组合仍需目视检查**。heatmap 计算文字对比只接受 #RGB、#RRGGBB 或 rgb(r,g,b)，不接受 CSS 变量字符串 |

## 六、自定义实现与图示布局

### 选择实现而非受制于配方

| 表达关系 | 实现起点 |
|---|---|
| 精确比较与范围 | ExhibitKit 或 ECharts 原生／custom |
| 趋势、结构和分布 | ECharts、Vega-Lite 或专用 SVG；分布需要真实观测支持 |
| 地理与关系 | ECharts／D3／ELK；地理、节点边与流量依据必须真实存在 |
| 分解与策略 | 图示渲染入口或自由 SVG／HTML；布局不冒充数值 |
| 过程与机制 | 节点／边／组的 SVG 或专用布局；关系要写含义和证据状态 |
| 取舍与行动 | HTML／SVG 或复杂图布局；没有日期不画精确时长 |
| 解释性信息图 | 自由 SVG、已有合法图片、图标；数据和装饰作用分明 |

不存在"所有图都必须经过固定几种配方"的要求。原生 ECharts、custom series、HTML 表格、SVG、D3／Vega-Lite／ELK 都可按需使用；**既有配方不适合时直接换实现，不要求先失败一次。** `render_echarts_svg.cjs` 也接受原生 option；custom series 需要函数时在 Node 中调用同一 API（JSON 不承载函数）。**图形、标签与模型计算都由作者检查，不能因为生成 SVG 成功就宣称语义正确。**

### 图示布局：显式坐标与自动布局

`node scripts/render_diagram.cjs input.json output.svg` 或 Node 的 `render(spec)`／`layout(spec)`。它用于节点、边、分组与文字的自由组合，**不是封闭的图型库，也不替作者判断业务关系**。

```js
const {layout, render} = require('./scripts/render_diagram.cjs');
const spec = {
  width:1080, height:540,
  layout:{direction:'auto', fit:'error', lanes:['客户','团队'], stages:['识别','决策','执行']},
  nodes:[{id:'a',title:'需求与约束',lane:'客户',stage:'识别'},
         {id:'b',title:'条件满足？',role:'decision',lane:'团队',stage:'决策'}],
  edges:[{from:'a',to:'b',label:'提交'}]
};
const positioned = layout(spec); // 实际尺寸、节点矩形、resolvedPoints
const svg = render(positioned);
```

- `lane`（或 `owner`）编码主体，`stage` 编码阶段；缺阶段时用无环边自动计算拓扑阶段。**循环要标 `role:'feedback'`／`feedback:true` 或显式阶段，不能删边假装成树。**
- `role:'decision'` 默认菱形、`role:'outcome'` 默认圆角，显式 `shape` 优先。**类型只是形状入口，不证明决策条件完整。**
- `direction` 支持 auto／LR／TB，auto 检查阶段列可用宽度并可在窄幅转纵向。`gapX`／`gapY` 是最小间距，边标签测量需要时自动扩大通道。字号继承既定角色，按交付字体测量换行，**不截字、不整体缩字**。
- `fit:'grow'` 默认把不够用的宽高扩到测量需要的最小空间，`layout_result.requested/actual/resized` 明确回传，**宿主必须使用真实尺寸，不可固定容器裁切**；正文版式推荐 `fit:'error'`，容纳失败由作者换方向、调空间或分面。
- 同一 lane／stage 的多节点共享单元格并按子行排列，节点高度按文字实际计算；`headers:false` 取消轨道标题，`laneBands:true` 可画低对比泳道底色。
- 边按当前节点边界定端口，通过可见性网格作正交路由并避开其他节点；自动模式重新求点，**不沿用旧的绝对折线点**。边标签用真实字体测量候选位置，**找不到空间即失败**。原值、作用／条件、假设状态由作者提供；连线默认等宽，**不凭无量化流程制造流量**。

支持以可容纳的阶段流程、泳道、机制与依赖为起点；**没有宣称任意复杂网络全自动最优构图**。不保证任意密集图无边交叉或共线，重复或交叉难以追踪时分面、调阶段；显式坐标路径不自动证明避让，需调用方核对。**整个图示仍须实际看 SVG 和最终 PDF。**

### 编辑而非仅保全

大量输入可用概览＋细节、分面、聚合、代表案例或全文附录。**由作者决定业务分组，保留重要异常和证据去向，不让运行库自动替你决定"其他"。** 同一展示中计算精度与显示精度分开，极小非零用适当小数或"小于"标签。主展品直接呈现主判断需要的比较并标出关键差额与分母；标题、导语、注释和页底总结不必重复同一意思。自定义结构依旧沿用主题语义、字体与来源，不增加图型配额。

## 七、咨询特色与概念图示索引

通用绘制规范：形状语言全篇一致（矩形＝实体或步骤，圆角＝起点终点，菱形＝决策，实线＝流向，虚线＝弱关系或未来态）；同类元素同尺寸；**框内文字不超过 2 行、每行 12–15 字（中文）**；图标一图一义、风格统一；**禁用渐变、投影、立体**。

选图先看这个表，再用上面的输入结构与读者动作核对是否真的成立。

| 图示 | 用在哪 | 边界与陷阱 |
|---|---|---|
| 曲棍球棒 ／ S 曲线 | 拐点之后的价值爆发；采纳周期定位与渗透率预判 | 预测段必须用虚线或阴影与事实区分，无依据的拐点是编造；有饱和段才用 S 曲线 |
| 成本曲线 ／ 经验曲线 | 成本位次与盈亏平衡产能；成本下降规律与定价战略 | 成本曲线是横截面位次、经验曲线是纵向规律；成本曲线要画价格线，否则看不出谁盈利 |
| 利润池 | "钱在行业哪个环节" | 只画收入不画利润等于没画；环节划分要 MECE |
| 市场地图 ／ 竞争格局 | 竞争定位与空白机会 | 两条轴都要是能推出行动的战略维度；点太多就退化成散点 |
| 2×2 与九宫格 | 优先级、组合管理、取舍定位 | 轴要拉开分布，象限必须命名；两轴定性才用它，定量用散点 |
| 价值链 | 环节分解、成本与价值归因 | 每个环节都要挂规模、成本或能力，纯装饰链没有信息 |
| 驱动树 ／ 利润树 | 定量根因定位，常与瀑布配套 | 每层标公式与数值，分解到"可行动"的叶子 |
| 议题树 | 问题结构化与穷尽性检查 | 同层必须同一拆分逻辑；它是过程工具，直接展示结论时不合适 |
| 评分卡 ／ 能力成熟度矩阵 | 方案比选与多标准决策；现状基线与差距一览 | 权重与评分锚点必须透明；语义色板必须带图例，优先用 CSS 表格而不是图表库 |
| Harvey ball ／ RAG 状态表 | 定性档级评估；项目与指标状态速览 | 档级 4–5 档封顶并带图例、填充方向不能混用；红绿必须同时配符号或文字，红色要挂下一步行动，全页绿灯等于没有信号 |
| RACI 矩阵 | 职责分配与治理沟通 | 每行有且仅有一个 A，A 与 R 不能同人 |
| KPI 仪表板页 | 状态总览与例行汇报 | 每张卡要有目标线，否则大数字没有结论；卡片不能多到没有层级 |
| Chevron 流程图 | 3–6 段线性推进 | 避免模板化观感，段内不能写成整段文字，只有重点段用强调色 |
| 泳道图 | 角色×阶段的责任与交接 | 交接点要显式标注；简单线性流程用它属于过度复杂化 |
| 循环图 ／ 飞轮 | 自我强化的闭环 | 3–5 个节点、箭头方向一致、每节点一句动作；线性流程不要用环形 |
| 金字塔 ／ 战略屋 | 抽象递进的层级；愿景、支柱与使能器的框架沟通 | 层级不超过 4–5 层且必须有递进逻辑；每层要有实质逻辑，否则是装饰塔或装饰屋，图形本身不承载论证 |
| 漏斗（概念版） | 分层筛选模型 | 层间要标筛选标准；有真实转化数据时改用数据版漏斗 |
| 时间线 ／ 甘特 ／ 里程碑 | 历史分期；执行计划与依赖；高层沟通 | 节点 5–10 个并分组；日期不确定就用阶段，不伪造时间轴长度；里程碑是交付节点不是任务，控制在 5–8 个 |
| 鱼骨图 ／ 组织架构图 | 因果分解；汇报关系 | 大骨之间要 MECE、小因不能写成症状；同级同高、虚线表示虚线汇报，跨级连线要理清 |
| 维恩图 ／ 齿轮拼图 | 集合交集；隐喻式表达 | 圆不超过 3 个、交集必须有标签；齿轮拼图多数场景是无意义的装饰，咨询正文极少使用，不如矩形＋箭头＋品牌色的规范图示 |

## 八、表达细节：视觉语法、注释与标签处理

### 视觉语法

用基线、对齐、分组间距表达结构；大面积底色、卡片和粗框仅在确有分组或状态含义时使用。直接标签靠近图形，总量、分项、差额各有位置，单位通常放图头、避免每个数重复长单位。参考线写业务含义，差异括号只连接实际比较的端点；**箭头的方向不能暗示不存在的因果。** 同实体沿用主题中的同一类别色，数学增减使用 delta 角色，好坏由经营含义判断。有直接数值时可弱化冗余网格，但零基线、必要尺度和分母仍保留。堆积和 Mekko 按系列稳定排序；**不为更均匀的色块移动数据，也不给零值虚构最小面积。** 图表内已把比较讲清时可用 analytical 阅读样式减弱外围说明框，普通 reading 样式仍然可用。

### 注释的计算契约

| 类型 | 计算 | 前提 |
|---|---|---|
| 绝对差 | end − start | 相同单位、期间含义与范围 |
| 相对变化 | (end − start) / start × 100% | start 大于 0；零或负基数改报绝对差并解释 |
| 百分点 | end − start | 显式声明输入是 0–1 的 fraction 还是 0–100 的 percent |
| CAGR | ((end / start)^(1 / years) − 1) × 100% | 正起止值与实际年数；三个年度观测通常是两个间隔 |

组件只验证数值，**作者仍需验证口径可比**。不得用数组长度替代实际年数，不把百分点标成增长率。先用原值计算，最后格式化；**不为让显示比例"凑到 100%"偷偷改原值**，必要时注释舍入误差。`difference` 对不适用输入报错；表格中缺失输入显示"—"；业务上不适用的比率应移除计算列，或写明文字说明。

### 标签放不下时改什么

① 为标题、刻度、图内标签、差异标注和引线通道分别分配空间；② 标签可移动、可换行、可外置，数据点、柱长、段面积和列宽不可移动；③ Mekko 或堆积段放不下名称和数值时改走同一侧的引线通道，引线就近绑回该段、不横穿绘图区，**不静默漏掉小片、零值和窄列**；④ 引线通道也排不下，或剩余绘图区读不出差异时，扩大模块、减少系列、拆页或换绘制路径；**组件报错是要改规格的信号，不缩小 viewBox 绕过，也不改成表格。** ⑤ 组件估宽只作提前判断，最终字号与窄列仍以原尺寸浏览器截图和最终 PDF 为准。

### 表格、流程与信息图

表格先区分标识列、原值列、计算列和解释列，数字右对齐、一列一种单位、总计由作者提供，**不自动相加比率**。数据条必须有包含零的统一 domain，列头显示量尺，未知值与零分开；文本较长时允许换行，必要时分页。流程的等宽阶段表示顺序，**不表示等时长**；没有明确日期时用阶段，不伪造甘特时间轴。阶段门禁用责任、交付、放行条件的对齐行组织；分支、反馈或跨部门依赖改用泳道或专门的关系图。信息图应由"关系＋数据或机制＋必要解释"构成，图标只有在帮助识别对象时使用，**不能取代证据**。

## 九、作者责任与表达底线

- 下列客观问题必须处理，不能用"选型已通过"豁免：数据口径不可比却要共轴、排序、相减或同色阶；图型要求了不存在的分母、层级、流量、日期、边或原始分布；**关键结论只能通过 hover 看到**；标签在目标媒介不可读且无法通过重排改善；需要手动移动定量数据点、伪造"其他"或把未知填 0 才能成立。
- 证据问题返回受影响的分析；媒介问题调整实现、布局或分页。换用其他实现时，保持关系语义、关键比较和证据边界。
- **放不下不是换表达的理由。** 类别数、连线数、小片、零值、长标签、窄列、渲染失败都不导致表格：`risks` 提示去哪里改布局，`problems` 指出哪几处文字实测遮挡或越界，`status !== 'ok'` 时 SSR 与浏览器侧都直接失败。修的方式是重排、换向、分面、总览＋局部或换绘制路径。
- 运行时**不自动决定 Top N、聚合、"其他"、抽样、因果解释或小倍数的业务分组**；这些改变证明责任的操作要由作者写回页面笔记。
- 硬输入上限仍可能直接报错，需要作者先分组或分页。**报错说明这一版还没完成：** 要么改到通过，要么如实标注该图未完成和具体阻塞。
- 现有 kit 只支持百分轴 Mekko，不实现堆积瀑布、单位轴 Mekko、任意标签自动避让或任意网络路由；不复制 think-cell 的编辑器、Office 联动或可编辑 PPTX，只采用数据派生注释、保守估宽与本地引线通道，**不声称同等的标签自动避让能力**。
- **不移植低字号、以 hover 承载关键信息、圆角卡片和动效偏好到 reading deck**；复杂关系图不要变成小字线路板。每项外部依赖固定版本并记录体积、离线策略与打印路径；升级 ECharts 后必须跑引擎、配方、三主题、PDF 与断网回归，**不能只改 CDN 字符串**。
- 复杂展品在页面笔记里记下：问题、关键来源与编码、所选实现路径、标签与密度计划、放不下时按哪条路径调整。简单页不建台账。
