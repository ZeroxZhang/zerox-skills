# 验收：先判断成品，再核对细节

**什么时候读这一份**：S5 装配完成、准备判断成稿时。

**读完要能做到**：以读者身份判断整份报告是否实现简报目标，逐页给出具体结论，分清 Blocking / Major / Minor，并知道自己这次该跑哪些检查、不该重复哪些。

格式正确不等于咨询质量。**分析、证据、视觉**三项状态写在 review 里，**工程**状态在 audit 的 `geometryStatus`；四项分开写，某项没执行就是未验收。工程检查通过只是其中一部分。

## 判断顺序

审查输入要先于工程结果：

**原始目标 → 用户已经明确的偏好 → 认可与否定的基线 → 作者规格 → 工程结果**

作者的规格本身可能有缺陷，不能只验证"按规格画出来了"。以读者身份看总览和每页：它有分析分量吗？视觉把关键关系展开吗？信息密度和风格符合本次简报吗？

先检查整页构思和全篇分工，再看局部几何。链条、差异、条件这类标题，要在图或表里实际找到；主视觉的面积和细节要匹配它的证明责任；重复的三栏摘要或大段空白，要回查是不是漏掉了关系、过度压缩材料或不当拆页。

样式优化要提供已认可的基线和明确的新增偏好，在同内容、同显示比例下比较实际字形、角色字号与字重、数字特性和强调范围。字体加载通过不能代替视觉继承验收；恢复基线和主动设计变化要分别说明。

## 三档检查：什么时候跑什么

`qa_deck` 有三档，**档位只决定"这一轮跑到哪"，不改变任何判据**——验收档与以前一样全量跑完，缺项写在 audit 的 `acceptance.missingStages` 里，不靠记忆。

| 档 | 命令 | 覆盖 | 用途 |
|---|---|---|---|
| 迭代 | `--tier iteration --pages 3`（或 `--pages 2,5`，**必须点名页码**） | 指定页的几何、字号、截图与视觉禁令 | 制作期反复改一页时用；只出该页 PNG，不出 PDF、不出证据清单 |
| 冒烟 | `--tier smoke` | 全页几何 + 打印媒体复检 + 首尾与逐页合同对账 + 总览图 | 整册做完、改动较大、准备进入验收前的一次整体自检 |
| 验收 | `--tier acceptance`（默认） | 全量：再加实际 PDF、逐页栅格、断网一致性、导航与深链 | 交付前唯一能作为审查与打包依据的档 |

**中途不要导 PDF。** PDF、逐页栅格与断网复检只在验收档跑一次；迭代和冒烟档没有 PDF，因此不可能被误当成交付证据。`--pages` 只属于迭代档：验收与冒烟必须覆盖全部页面，否则给不出整稿结论；迭代档反过来必须点名页码，因为它的缺项清单（不跑首尾对账、总览图、planner 核对）假定这一轮只看被点名的那几页。两种越界用法都会被直接拒绝，不会跑一半才失败。要看整册但不出 PDF，用冒烟档。

只有验收档产出 `evidenceManifest`。缺证据清单的 audit 无法聚合出可交付的 review，`package_delivery` 也会点名拒绝。

## 边做边看：单页自查

`node scripts/preview_page.cjs deck.html <页码|--all> [--out 目录] [--json]` 供 S3/S4 逐页使用：出这一页的 PNG，跑便宜的几何、字号、视觉禁令与关键语义核对，列出**阻塞**、**需目视判断**、**必须实际看图**三类。

它不产出 `audit.json`、不产出证据清单、不产出任何验收结论——**迭代产物在物理上不能冒充验收证据**。这与 `qa_deck` 共用同一个逐页探针，所以两处判据不会漂移。

用法是**做完一页就看一页**，而不是等全册装完再一起看：在最便宜的时点发现"这页不成立"，回到 S3/S4 改这一页，比在 S5 之后回头重做整册便宜得多。预览输出的截图仍然要自己打开看——它只覆盖可自动测量的部分。

它渲染的是装配后的 `deck.html`，所以循环是「改片段 → `assemble_deck.cjs` → `preview_page.cjs deck.html <页>`」。装配是无浏览器的纯构建，重跑一次是秒级；比起等 PDF、等整册验收，这个开销可以忽略。若只想改这一页、不想动别人，用 `--tier iteration --pages <页>` 跑 `qa_deck` 拿到同一页的完整判据与截图。

## 整页检查清单

每页都要能回答这八条，判断要落到具体页和可见结果：

1. 主证据是否先被看见。
2. 标题里的关系是否真的展开——链条、差异、条件要在展品中找到，不能只在正文或页底说明里读到。
3. 说明是否贴近它解释的对象。
4. 全页及模块内部的空白是否有用途（分组、强调、阅读节奏）。
5. 同层文字基线、共享比较轨道、实际绘图区是否对齐。
6. 来源空间是否安全，正文或大框不得挤住来源和关键限定。
7. 是否出现禁用色条模块。
8. 全篇是否重复同一弱结构——先读 audit 的 `pagesInventory`：形式与族的分布、最长的连续同形式段都在里面，再对着具体页判断这个重复是"本页确实需要"还是"选型前就被压成了同一形状"。

细则：

- 短文大空框、内容集中在上半页、外框齐而内容错位，都要具体判断并修复。
- 不要求独立模块机械等高；合理的非对称和有目的的留白要保留。
- 禁止用拉高表格行、扩张背景、堆字或增加无关内容取得表面均衡。
- 只写"层级清楚、无溢出、没有遮挡"不足以支持整页通过；没有具体的成品判断就保持未验收。
- 已确认的构图缺陷先返工，工程精度通过不能抵消。
- 审查者个人口味不强加给作者；但用户明确提出的构图、留白、对齐和禁用色条要求属于本次任务合同，不能以"审美偏好不构成 Major"放行。
- 修改后要重新看受影响的完整 HTML 页和实际 PDF 页；局部截图不能证明整页均衡。

## 内容与编码复核

整页成立之后，再核对展品和数字本身：

- **数字与口径**：计算闭合、数字一致；期间、单位、分母、范围可比；事实、估计、示意与建议区分。不同口径不能因为外观一致就放在一起排名。
- **端点与派生量**：差异端点绑定源值；百分比、百分点、增长率的分母与间隔正确；**零或负基数不能硬算常规增长率**。
- **总量与构成**：堆积图区分总量与份额；百分比轴的宽度要对应总量；零值不画假面积，以位置标记加"0"说明；小片与窄列用引线标注绑回该段，**不能靠另一张表替它说话**。
- **表格语义**：单位、数值对齐、统一的数据条量尺、缺失与总计的语义明确。
- **图示语义**：责任、交付、条件与关系可读；顺序不是因果，等宽阶段不是等时长。
- **派生数同源**：配方、图内注释和标题里的派生数来自同一份输入，不分别硬编码。
- **可追溯**：抽查至少一个大表、一个长文本来源和一个派生指标，确认没有把整表整段当成单一证据，也没有从未编码的文本生成伪精确统计。
- **容量超出时**：调整布局、聚合、分面、换实现或分页；保持实际可读，重要异常和明细有去向，**不把未知填 0**。
- **声明与成稿同型**：`data-form` 声明为图形实现（`kind:'svg'`）的页必须真的出现 SVG；只有表格就报错。多展品页按主区核对，不能因为同页另有一张表或一张小图就默认通过。机器只能查出这类可识别的类型不一致，**主图是否被表或其他形式暗中接管，仍要靠看图判断**。
- **删掉无意义的东西**：装饰、复述、填充卡片；同一知识点避免重复全量。正文保留足够证据，方法明细进附录并回链。
- **不按复杂程度打分**：保留普通表格或条形的页面可以获得最高完成度评价，不按复杂程度或与某商业工具的相似度评分。
- 遮掉外围解释后，图或表应当仍能支持它那一层的子判断；新增的括号、数值列、颜色或箭头，每一样都要说得出减少了什么理解成本。

## 禁用装饰色条

报告不得出现以装饰性边条强调的文字、判断、说明或数字模块：注释/判断块的侧边条、数字卡片的顶部色条，以及挪到下边、换颜色、换类名、用伪元素、阴影、渐变或 SVG 绘制的同类外观。白底卡片也不能以"没有浅灰背景"豁免。

检查方式：

- 自动检测优先覆盖真实计算样式中的典型装饰边条，包含伪元素、内联样式和常见的绝对定位窄块路径。
- **已识别的禁用样式必须返工，不能只给一条可忽略的 warning。**
- 不要把 CSS 类名黑名单当作完整覆盖：换类名、拆成顶层元素、用伪元素或 SVG 模拟同样禁用。
- 自动检查识别不了的对象——自定义 SVG、位图、复杂渐变、过小的文字装饰——由实际看图补足。
- 数据条、坐标轴、误差线、关系连线、表格必要分隔线和 quiet 母版不属于禁令，不要误杀。也不能为了消灭色条而删掉关键限制或数据内容。
- 去掉边条后要按内容重排，不能留下同样大的空框。

`qa_deck` 的 audit 会把典型外观报成 `V-DECORATIVE-EDGE`、`V-DECORATIVE-PSEUDO`、`V-DECORATIVE-SHADOW`、`V-DECORATIVE-STRIP`；把需要人工确认的路径记成 `V-SHADOW-MANUAL`、`V-BACKGROUND-MANUAL`、`V-PSEUDO-MANUAL`、`V-RASTER-VECTOR-MANUAL` 提示。这些提示不是通过，必须实际看图。

## 视觉均衡的返工闭环

自动检查只给线索，不作审美判定，也不能用统一填充率代替判断：

- `V-EMPTY-MODULE`：背景框里的文字下方有大段空置，检查是不是被轨道伸展成了空框。
- `V-BODY-REMAINDER`：正文实际对象下方有大块剩余空间，检查它的分组、强调或节奏用途。
- `V-SOURCE-COLLISION`：正文对象进入来源区域，检查来源安全区与关键限定。

确认存在不合理留白、应齐未齐或明显重心失衡后：回到分析与整页构思重排 → 用 `preview_page.cjs` 边改边看这一页 → 全册装完再跑验收档复看受影响的完整 HTML 页与实际 PDF 页 → 局部截图不能作为整页证据。

返工不必重跑整条链。**改一页只作废一页**：页面 DOM、命中该页的样式和该页渲染图三者构成这一页的失效半径，其他页仍可引用旧审查（条件见[交付契约](delivery.md)的"有限继承"）。所以先确认改动落在哪一页，再决定要复看多少页——但改了公共样式或共享依赖时，范围就是全篇。

## 主题与实体一致性

- 继承本次任务已经确定的主题，不自行重选；主题、字体与配色互相独立，换配色不触发换字体。
- CSS、图表 series 与 visualMap、SVG、表格和状态列的颜色，必须来自同一个 `assets/deck-themes.js` 预设。
- **数学上的正负不等于经营上的好坏**：品牌绿不自动表示达标，渐变不编码类别；状态要同时有文字或符号，不能只靠颜色。
- 验收实际 fill 与 stroke、文字反差 ≥4.5:1、灰度下的直接标签、打印色阶，以及图例的上下限。
- 改了主题或换色后必须重建静态图并重新截图与导出 PDF；只换 CSS 颜色不算通过。

## 母版与组件合规

先读[母版与排印](type_frame.md)的检查小节，再看这四项。`qa_deck` 有对应告警，但结论由实际看图给出：

- **边界显式声明**：每个内容页都有 `data-frame-boundary="line|integrated|space"`；封面与全出血页用 `data-frame="off"` 并同时声明 `space`。没有声明的页面视为未完成母版选择。
- **边界不重复**：标题区隔线与正文首排必要结构顶线不并存。首排已有表格上边这类分区线时用 integrated；看到"灰线紧贴正文顶线"的双线即缺陷。不得为了合并母版线而新增装饰色条。
- **禁用装饰色条**：见上文。
- **页边识别**：左缘短标与右下折角不被内容遮挡、不借用数据强调色；正文 margin 与 `--frame-rule-offset` 保持配对，压 margin 不调 offset 会把线贴到正文上。

未执行或没看页面时如实写 not_reviewed，不能拿"自动告警为零"代替目视结论。

## 分析前置与内容复核

- 复杂分析、重大结论时，要在 S2 形成核心结论之前安排独立复核，不能等页面做完才检查推理；触发条件见[分析](analysis.md)。**关键推理有争议时同样要安排**——这是判断要求，不改变 `task.json` 的派生规则，作者要自己识别并如实记录实际独立性。
- S5 复核时读取实际保留的分析底稿、来源和最终标题，重点核对：方法前提、关键反证、目标/预测与建议条件有没有丢失。
- editorial 用原文定位和必要核对记录执行内容复核，不补建台账。
- 分析 ready 只说明当前有限结论可以进入制作，不代表事实外部核验、视觉或工程已经通过。
- 核对作者声明的少量关键否定、分母、状态与条件是否完整、是否仍解释正确的对象。总体文字覆盖率或"数字还在"都不能证明语义完整。
- 不得以节省空间为由删掉会改变结论的限制。

## 工程证据

- single-file 入口与 offline 自包含要分开说；离线时关键证据必须完整，不能只提示"图表不可用"。
- 实际翻页、`#3` 深链、G/Esc、全屏、缩放、Home/End 都要实际操作，不只读代码；页码与导航要统一。
- 每页截屏，逐元素检查越界；检查 SVG 文字碰撞与截断；SVG 与 canvas 的尺寸问题区别对待。
- 捕获 console 与 pageerror；图表必须在可见时初始化，打印前所有实例完成。
- 普通文字对背景的对比度 ≥4.5:1，来源也是文字，不豁免。
- PDF 页数等于 deck 页数，且关键图和标签确实进入打印；文件存在不算成功。
- ECharts 版本与 `package.json` 一致；离线交付里的图已静态化或依赖已内联，断网不缺主证据。
- 字体在就绪后才测量；实际平台字体来自指定资源，无意外系统回退与伪粗。
- PDF 字体已嵌入且可检索；冷缓存断网后字体与逐页几何一致。
- HTML 内嵌的 PDF 与独立 PDF 文件的 SHA-256 一致；定稿 HTML 修改后必须重新生成、验收并打包 PDF。
- 页级失效半径要真的用起来：改完第 5 页后重跑验收档，`evidenceManifest` 里只有第 5 页的三个摘要会变。若发现其他页的 `pageStyleSha256` 也跟着变了，说明这次动到了公共依赖或判不出作用域的样式，那些页同样要复看——不是工具误报。

跑 `node scripts/qa_deck.cjs deck.html output-dir` 生成自动检查与逐页截图。**自动通过只能报告几何与运行通过，每页原尺寸图必须实际查看。** 灰度、PDF 和总览也要看；母版与组件合规属于同一轮视觉检查。

**工具不能看图时**：视觉状态写"未验收"，不能用自动通过、像素统计或告警数量替代，也不能把未执行的检查写成通过。

## 问题级别

**Blocking**：数据或编码误导、核心证据缺失、无法显示或打印、关键文字被遮挡。

**Major**：证据链、关系表达、页面重心、层级、色义或图注缺陷显著影响理解；或未兑现本次明确的成品质感与构图要求（含禁用色条、逐页视觉均衡、有效内容对齐）。仅有风格差异不自动判 Major；要说明具体所见、任务依据和影响，不按空白比例或图型数量定级——**但"不按比例定级"说的是不拿一个数字替代判断，不是说不许量**：密度档位触发的空置是实测值，要判它是否成立，看的是那段空白有没有说明得出的功能，不是看它的百分比够不够体面。

**密度档位与告警处置。** 交付默认 `compact`：展品区底部余量超过两成、模块之间空档超过两成、或单模块内空置超过百像素且占模块四分之一以上，由 `qa_deck` 直接报错（封面、封底、参考资料按设计豁免，只报诊断）。要松排版必须显式写 `densityPolicy:"normal"`。其余告警仍可在 `warningReview` 里判"接受"，但**处置凭据要能被核对**：写清按实际尺寸看到了什么、这段空白在做哪一件事，而不是"属有意留白"这一类叙述。多条同类告警一并接受时，分别给依据，不要把一句话复制到每一条上。

**Minor**：不影响理解的小间距或措辞瑕疵。

**未执行的检查另列**，不归入 Minor 糊弄通过。

## 底线与建议分开

| 类别 | 如何处理 |
|---|---|
| 数据、推理和表达真实性 | 数字可复核；比较口径成立；定量编码正确；重要反证与未知不被隐藏。必须成立，不能以布局自由豁免 |
| 成品可用性 | 核心文字与展品可读、进入 PDF；离线契约和同版哈希成立；失败要修复 |
| 用户明确的视觉要求 | 禁用装饰色条；逐页视觉均衡、有效内容对齐、来源空间与合理留白必须兑现，不能当可选美化 |
| 设计默认值 | 标题通常两行、数据通常 15–16px、边距与布局比例是建议，在实际媒介中效果更好可以调整 |
| 工作过程 | 阶段可合并，少量文件可覆盖全流程；方法与图型记录用于复杂任务追溯，不要求每页全填 |
| 库内部阈值 | 配方的行数、字号或节点上限只表示这条实现路径的容量；可以换原生 option、专用 SVG 或其他工具，但不能据此降低原始分析深度 |

"检验不适用"和"未检验"不同。检查范围要真实；精简不等于把未知写成 PASS。

## 不要机械套用的流行规则

外部流传的"图表铁律"多数在本项目不成立，不要拿它们判 Major：

- 不禁饼图，也不设占比配额；饼片数取决于可读性，常见 3–5 片是建议。
- 双轴不是绝对禁用，但要谨慎，优先分面或指数化并写明基期。
- 类别颜色没有统一的三色上限，但颜色必须有图例或语义。
- "一页一观点"不等于一图：一个主判断可以由多个共同证据支撑，也不按标题逗号个数拆页。
- 白底是本项目默认，不是所有报告都必须遵守的普遍规则。
- 瀑布图不依赖特定工具；允许流程图，重点检查关系是否有信息。
- 二维定量数据不用 3D 装饰扭曲——这一条是硬性几何要求。

判断一页要不要保留时问：删掉它会失去哪项必要证据或决策信息？没有损失才合并或删除。

## 维护时的两条纪律

**先建立基线，再归属失败。** 改动后跑全量回归，失败用例未必是自己造成的。先用 `git worktree add .baseline HEAD` 拉一份干净检出（软链技能目录下的 `node_modules` 即可），在**改动前**的代码上跑同一批用例，确认哪些本来就红，再动手修。把既有的红算成自己引入的、或把自己的红推给既有问题，都会让后面的判断失去依据；报告里也要分开写。

**突变反例必须真的违反被测不变式。** 用"改 4px 必须被检出"证明检查器有效时，突变本身要保证破坏了那个关系：把两个标注挪到一起时，如果它们的 `text-anchor` 不同，挪到同一坐标也未必重叠——那样的"通过"什么都没证明。每次突变都要断言**具体错误码**被报出来，不是"有错就行"。

## 按变更选择检查范围

常规制稿不需要重跑整个组件库。按这次实际改了什么选：

下表默认环境已按 [安装说明](../docs/usage.md#安装与运行) 装好：克隆后先 `npm ci`，再 `npm run setup-fonts`。少了 `.font-venv` 时字体相关的回归（如 `test_assemble_deck`、`test_dense_inputs`）会以 `No module named 'fontTools'` 失败，那是缺前置不是代码问题。夹具缺失的测试会自己生成，不必先手动跑构建脚本。

| 任务 | 建议执行 | 不要求重复执行 |
|---|---|---|
| 新 deck／大量内容改写 | 核对关键事实与计算、标题与证据一致；逐页用 `preview_page.cjs` 边做边看，全册装完跑 `qa_deck` 验收档并实际看逐页与 PDF | 整套组件、字体、引擎单元回归 |
| 少量文字或数据更新 | 受影响的来源、计算、标题、图；先 `--tier iteration --pages 受影响页` 自查，再重打包字体、重建 PDF 并跑验收档检查受影响页 | 无关分析与无关组件测试 |
| 只改某一页的样式或版式 | `--tier iteration --pages 该页` 自查并看该页截图；确认改动没碰公共样式后，验收档重跑时只有该页失效 | 无关页面的复看与整册视觉复核 |
| 自定义图表或图示 | 验证该图的映射、标签、边、流量、尺度；最终截图与 PDF | 逐一遍历全部图型 |
| 旁解读／标注改动 | `test_annotation_layer.cjs`（契约、语义、碰撞回退）、`test_annotation_browser.cjs`（真实 bbox、引线两端绑定、4px 突变反例）、代表成稿截图与 PDF | 不相关的行为测试 |
| 页面合同／形式枚举改动 | `test_pages_contract.cjs`（枚举与真实实现一一对应、标注入口真能出图、反单调门禁、成稿对账、遍历覆盖）、`test_assemble_deck.cjs`、`test_qa_integration.cjs`、`test_delivery.cjs`、端到端样张 `build_pages_contract_example.cjs` | 不相关的图型算法回归 |
| 选型方法／实现入口改动 | `sweep_forms.cjs --check`、`test_pages_contract.cjs`；独立前向验证内容匹配、候选丰富度及不成立图型的排除 | 无关图型算法或跨模型实验 |
| 可选 planner 接入改动 | `test_viz_planner_loader.cjs`、有实际安装时运行 `test_execution_contracts.cjs` 核对数据版本与可见图元 | 不为日常选型安装外部技能 |
| 引擎功能或默认示例改动 | `test_engine`，受影响样稿 QA；导航、打印、离线 | 未改方法的完整研究验证 |
| 图表运行层或不退表规则改动 | `test_echarts_recipes.cjs`（画布不足只报问题、零值位置标记）、`test_analysis_exhibits.cjs`（小片／零值／窄列引线通道）、`test_exhibit_kit.cjs`、`test_theme_browser.cjs`、`test_engine.cjs`、`test_dense_inputs.cjs`、`test_pages_contract.cjs`（`fallback` 被拒）、`test_qa_integration.cjs`（声明为图却只有表格要失败）、随包样稿重建及代表成稿 | 不相关的交付 UI 或字体回归，除非影响打印或下载 |
| 字体打包或测量改动 | typography、font_metrics、browser、svg_scaling 及代表样稿 | 不相关的分析行为测试 |
| 交付或 QA 改动 | delivery 及 QA 逃逸测试，正常稿能通过；PDF 渲染改动另跑 test_pdf_canvas.cjs（渐变／透明组真实像素）；分档或逐页探针改动另跑 test_qa_integration.cjs 与 test_bookends.cjs | 全部方法卡重新研究 |
| 证据归属或失效半径改动 | `test_review_inheritance.cjs`（继承结构与新判据）、`test_evidence_scope.cjs`（逐页样式分桶与保守归全局）、`test_review_delivery_v3.cjs`、`test_qa_integration.cjs` | 无关图型或字体回归 |
| 分析或编排规则大改 | 独立前向案例，覆盖新行为与合理轻量路径 | 机械执行固定份数的报告；需要扩大验证时再扩 |

`qa_deck` 把标题超过建议行数、文字接近字号基线等输出为 warnings，交由实际视觉判断；明显越界、极小可见文字、打印丢展品、文件不同版输出 errors。不要为了消除 warning 牺牲正确表达，在 review 里解释影响即可。

每页 0–4 评分是可选的诊断工具，不是交付门槛；分数不能代替具体缺陷，有问题就记录页码、所见、影响和修复依据。

完整报告的首尾页另有专项检查，见[首尾页面](bookends.md)。
