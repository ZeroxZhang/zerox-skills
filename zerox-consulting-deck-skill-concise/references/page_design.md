# 整页创作：把关系变成可见的论证

**什么时候读**：S3 逐页构思阶段，动手做任何新页之前。
**读完要能做什么**：用一句话说出这页要让读者看出的关系；把这句话变成画布上可见的结构；判断整页是否成立——而不是只判断元素有没有放进去。

先有对材料的理解，按[图表选型](charts.md)确定关系和表达，再选组件与布局。主技能对整个画布负责；现成的图、表、组件和 planner 建议都只是构思的材料。

## 先形成一个页面构思

用一句话说明读者要看出的关系，并想清楚如何让它直接可见。例如：哪里差异最大、什么约束在回收、谁向谁付款、哪些条件共同成立才允许行动。标题和段落可以说明关系，图形的顺序、分组、连接、对照和尺度应该进一步帮读者理解它。

把原始材料中的动作、主体、层级、条件与证据展开。主视觉可以是完整机制图、比较矩阵、复合数据图或信息图；旁注与微型图贴近相应对象，另有证明责任的补充才单独分区。允许一张大展品统领全页，也允许多个互补展品。**不要把"主证据＋解释"固定成左图右字。**

文本的图形转译**不是在段落外画框**。它应该显露文字阅读时需要来回推导的结构；**如果画完框之后读者仍要在段落里寻找对应，那还没有完成转译**。示意插图和矢量图标可以帮助识别主体、解释对象、建立导航或形成视觉焦点，其作用由内容决定。定量图按真实数据映射，定性图的箭头和分组说明语义，假设与待验证条件可以明确呈现。**不用"装饰无数据"一概排除视觉创作**，也不以无关装饰掩盖内容组织不足。

## 从整张画布反推布局

默认 16:9 为 1280×720；reading 左右约 40px，标题通常占 72–92px，正文可用约 480–520px，来源另留可读空间。**这些是起始预算，不是定律**，实际按标题与来源高度、字体和母版计算。4:3 需要重新布局，不能等比缩放。

先确定主视觉需要多大才能充分表达，再安排互补证据、说明和阅读路径。通过位置、面积、字号和对比度建立主次；**实际图形区域决定视觉重量**，SVG 外框、表格外框或背景占满不能代替有效内容。关键限制可能与主证据同样重要，不能因为叫"备注"就自动降级。

共享维度的比较要建立共同列头、尺度或行轨道；独立补充不强配行，不强齐底边。收束短说明后，把余下空间纳入全页重新分配：展开主图的必要分支、把证据放回被解释的位置、组合互补关系，或调整页面分工。**不要让所有模块都自然高度贴顶之后就结束设计。**

全页要有明确重心和连续的阅读路径。大面积留白可以建立焦点、分组或节奏，也可能暴露关系没展开、内容不足或布局未完成——判断它的作用，而不是计算统一填充率。若连续多页都只占上半部，先查全篇的内容组织与实现习惯，不要逐页加空框、拉行距、垂直居中或添加重复结论。

**判断要落到实测，不能落到"这是设计"。** 交付默认 `compact` 密度档位：展品区底部余量超过两成、或模块之间出现超两成的大空档，会被当错误拦下，封面/封底/参考资料按设计豁免。要主张某段空白是分组或节奏，就用实测值说明它在承担什么；**"上对齐之后自然留下的空白"不是理由，那是默认排版，不是决定**。这一条不推翻上面那句——它只是要求"留白是有用的"这件事被真的判断过，而不是被默认为成立。

在继承主题和字体角色的基础上设计比例、形状、线条与色彩节奏，让页面有视觉吸引力和完成感。

## 每页必须完成的空间与对齐判断

这一节是硬性交付要求，不是可选美化。每页都要检查下列实际对象及其关系；检查真实内容边界，而不是只检查容器。

| 检查层面 | 要看什么 | 不接受的替代做法 |
|---|---|---|
| 整页重心 | 主证据的面积和细节是否匹配证明任务；左右与上下内容重量、阅读动线、页面节奏是否成立 | 背景占满就称内容饱满；所有内容贴顶后称剩余空白"简洁" |
| 留白用途 | 最大空白以及模块内部空白是否确实用于分组、强调、阅读或节奏 | 只写"有意留白"而无可见作用；拉行高、放大外框、添无关图标、重复结论填空 |
| 模块关系 | 同层模块该共享的起点、列轨道、边界及间距是否一致；主辅层级是否清楚 | 不问关系一律等宽等高；把独立补充强拉齐底边 |
| 内容对齐 | 同层标题的**真实文字基线**；比较行的**数值轨道**；共享尺度的**实际绘图区边界** | 容器同顶就当文字同基线；SVG 外框同高就当绘图区对齐；逐标签偏移补洞 |
| 来源与限定 | 来源和关键说明有独立安全区，贴近对应对象；正文收缩后重新布局 | 正文或大框挤住来源；把关键解释压成脚注微字 |

**执行与返工路径**：在页面笔记里写明本页需要成立的少量空间与对齐关系；字体就绪后测量真实对象。先做有代表性的复杂页，检查"整页截图＋原尺寸局部＋实际 PDF"，在复用版式之前先修复公共布局问题。每页定稿后都要过一遍上表；改动模块内容或高度后重新看整页，不能只看改动局部。

保留合理的不对称、有目的的留白和自然高度的长表。已确认的不合理留白、应齐未齐或明显重心失衡属于必须修复的成品问题；不能以"只是审美"或"工程 PASS"放行。无内容支撑的独立页按论证合并或重新分工；有分析遗漏就补回有价值的关系，不为填满画布虚构材料。

关键否定、分母、状态和适用条件要贴近各自的解释对象，并在 HTML 与 PDF 中都保留下来。不要求每句话都加标记；绑定方式与检查边界见[精度与标注](precision.md)。

## 整册节奏与页面去留

总览、机制、对比、论证和决策承担不同的阅读任务，应从关系出发形成相应布局。**相邻页面重复三栏段落、同样的短条图加长说明，可能意味着材料在选型之前就被过度摘要**；这时回看原材料中尚未表达的关联，而不是轮换外观皮肤。

保留能让人方便查值的表格，也保留有意的简洁页。若一页只复述上一页，或只能给出几条通用建议，优先重新分工或合并；**"一页一个判断"不要求每条摘要独占一页**。图表与图示的组合以新增理解为准，不设数量和占比要求。

## 从构思到实现

笔记记录四项即可：**证明什么、哪些关系如何可见、主次和阅读顺序、空间及关键对齐的取舍**。复杂页再展开数据映射、行列轨道、端口和标签预算。简单页不必建坐标台账。

### 构思要落成 pages.json

**内容和它的组织形式必须在这一步一起定下来**，而不是先写标题、实现阶段再临场找图。逐页把 `proves`（这页要让读者看出的一个关系）和 `form`（用什么形式实现它）写进 `pages.json`，并在 `task.json` 绑定。字段与规则只有一份来源：[交付契约](delivery.md)的 pages 一节。

- `form` 取自 `assets/deck-forms.js` 的实现入口；候选图型先按内容选择，不能被组件清单限制。未封装的原生图、组合或手写图走 `svg.custom`，补 `visual` 指明实际表达，成稿写相同 `data-visual`。
- 一页多展品用 `regions` 写清主辅与分区，不要留给实现阶段即兴决定。
- 图上的旁解读写进 `annotations`，见[证据与表达](exhibits.md)的"旁解读"一节。
- **相同表达第 3 次起、或连续三页相同表达，必须写 `repetitionReason`。** 通用 SVG 按 `visual` 区分，不能把不同图误算为重复，也不能靠别名伪造丰富度。 这不是图型配额，是"重复必须是被解释的决定，不能是默认"。写不出理由，通常说明材料在选型前就被压成了同一种形状——回原材料找还没表达的关联，而不是换个外观皮肤。

使用目标字体测量，继承原有角色层级；表格和说明内容高度自然，主图按实际绘图区重算。统一字体与 line-height、使用真实锚点来保证同层基线，**不能靠逐标签偏移修补**。共享几何与锚点的声明方式见[精度与标注](precision.md)。

`.annotation` 只保留语义用途，不附带装饰边条，也不是每页必备的收尾槽。**禁止侧边色条判断块与顶部色条数字卡**（含自定义类、伪元素、阴影、渐变和 SVG 同类外观）；移除色条后要同步收束空框、重排内容，不能只隐藏边框。数据条、轴线、关系线、必要结构分隔和 quiet 母版不在禁令内——完整规则见[母版与排印](type_frame.md)。

### 可选骨架

需要实现骨架时再查下表。它只说明各原型能承担什么阅读任务，**不规定常用优先级、图型数量、段落数或填充率**；比例和具体绘制方式由内容决定。

| 原型 | 能承担的阅读任务 | 可用结构与关键取舍 |
|---|---|---|
| 纯文本 | 需要精读的论证、原则或引文 | 按论证层级排版；有主体、依赖或条件时先判断图示是否更清楚，不默认把定性材料做成段落栏 |
| 单图表 | 一个充分展开的核心比较 | 主图统领正文，标题、图例、标签共同布局；没有新增含义不另加收尾条 |
| 图表＋解释 | 数据与机制或边界需要配合 | 解释贴近对象，可侧置、嵌入或置下；主辅面积按证明责任决定，不默认 2:1 或等高 |
| 多展品 | 互补证据或同口径分面 | 按阅读顺序安排，共享有意义的尺度与锚点；避免重复数值和各自居中 |
| 表格 | 精确查值、共同维度比较 | 同行轨道、单位和列头清楚；微型图帮助扫描，行高由内容决定 |
| 框架／概念 | 层级、驱动、约束、反馈或权衡 | 关系决定形状与连接；必要证据和反例靠近关系，不为套框架强凑节点 |
| 流程 | 主体之间的动作、交付与分支 | 可用泳道、连接或路径，明确方向与条件；不默认等宽箭头条，顺序不冒充因果 |
| 时间线／路线图 | 阶段、责任、依赖和里程碑 | 有真实日期才按时间映射；定性阶段明确非等时，路径与责任保持可读 |
| 对比 | 共同维度下的方案取舍 | 矩阵、双路径或分面对照；相同维度对应，避免两边各写不同问题 |
| 执行摘要 | 综合已经成立的关键发现 | 可用系统图、证据结构或短论证；让关系与主次可见，不强制列表或三栏 |
| 章节分隔 | 过渡、导航、主题预告 | 允许有意的低密度和留白，不套正文的密度要求 |
| 附录 | 补充核对、方法、明细 | 按内容使用上述结构，保留与正文的对应和原尺寸可读性 |

已有样式在 `assets/consulting-layouts.css` 与 `assets/deck-geometry.css`，装配时自动内联。上面几行的结构要在具体页面上选型时，读[单页布局选型](layouts.md)：按读者任务分族给出阅读路径、取舍、什么时候不该用，以及可直接粘贴的 `regions`；配套的可浏览图谱在 `assets/layout-atlas.html`（双击即开，离线）。可用的页面级结构：`.evidence-grid`、`.layout-split`、`.layout-three`、`.layout-paired`、`.layout-stack`；展品容器 `.exhibit`（含 h2、.unit、.graphic）；文字结构 `.evidence-note`、`.annotation`、`.decision-strip`、`.matrix-note`；表格 `.data-table`（.num、.group、.selected）、`.analytical-table`；状态 `.status-label` 与 `.status-good/.status-risk/.status-caution`；数值轨道 `.precision-table`、`.precision-row`、`.precision-bar-track`；版式 `.proof-layout`、`.plot-stack`。名称表示的是一种可选结构，不是固定配方；相邻页面可以有完全不同的构思。

## 整页成立才进入交付

总览看主次与全篇节奏；原尺寸看关系、阅读顺序和信息量；关键局部看排印与标注。实际回答这四个问题：不读全部段落，能否找到标题里声称的关系？主视觉获得的空间是否匹配它的复杂度？最大的空白服务什么？这一页给全篇增加了什么？

**如果只能说"元素都在、对齐了、没遮挡"，整页判断还没有完成。** 对照用户明确目标作出具体结论；未达标先改构思和结构，不能把布局未完成降级为可选美化。HTML 与实际 PDF 都要看，几何检查只是补充证据。
