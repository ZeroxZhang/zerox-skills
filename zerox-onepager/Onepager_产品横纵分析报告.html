作者: Zerox 产品研究

一、一句话定义

Onepager 不是一个普通的 Markdown 转图片工具，也不应该继续被定义为“九种风格的海报生成 Skill”。

它真正有机会成为的是：

面向 AI Agent 的单页视觉编译器：把复杂内容编译成可信、可控、可复现、可继续编辑的单页视觉资产。

这里的关键词不是“漂亮”，而是“编译”。

漂亮只是一次结果。编译意味着存在稳定输入、结构化中间层、明确规则、确定性输出、错误报告和可重复构建。上一轮优化已经补上了质量门禁，但如果产品只停在“Prompt 生成 HTML，再截图成 PNG”，它仍然是一个能力很强的一次性生成器，还不是能长期积累用户资产的产品。

二、核心结论

2.1 Onepager 当前最强的不是模板，而是内容判断

绝大多数同类项目从排版开始：用户给 Markdown，工具负责换主题、分页和导出。Onepager 从内容理解开始，会判断信息类型、叙事结构、密度、关键数据和视觉层级。这是它和 Madopic、MD2Card、markdown-poster 最实质的区别。

用户真正付出的高成本，往往不是把字变成图片，而是决定：

  • 这一页到底要讲什么；
  • 哪些信息应该删掉；
  • 什么应该成为视觉中心；
  • 内容之间是流程、对比、层级还是论证关系；
  • 读者看完应该记住什么、做什么。

Onepager 已经在 MECE、金字塔、SCQA、So What、类型差异化等部分积累了大量规则。这些规则不是设计装饰，它们是产品的内容决策引擎。

2.2 当前最大的问题是“生成前太重，生成后太轻”

生成前，用户需要面对尺寸、风格、密度、类型、BigNumber、署名六个维度。只计算四尺寸、九风格、三密度、四类型和 BigNumber 开关，就有 864 种基础组合，还没有算 focus 和 B9 子模式。

这套组合系统对设计者有价值，对普通用户却是决策负担。

用户说“把这份方案做成一页图”，本意是减少设计决策，不是接手一个设计控制台。Agent 应该先给结果，再让用户沿着少数高价值维度调整。

生成后，用户拿到 HTML 和 PNG。理论上 HTML 可编辑，实际上多数目标用户不会打开 CSS 修改某个区块。他们真正想说的是：

  • 第二块文字太长，压缩一点；
  • 锁住标题，只换下面的布局；
  • 这组数据不要 BigNumber，换成对比；
  • 保持这个品牌，再做一个 16:9 版本；
  • 给我三个方向并排比较；
  • 只重做右下角，不要整张重新生成。

这些都是产品级编辑动作。当前 Onepager 仍主要依赖 Agent 重新理解自然语言并修改最终 HTML，缺少稳定的局部编辑模型。

2.3 最大的直接威胁不是另一个海报 Skill，而是 AntV Infographic

截至 2026-08-08，AntV Infographic 约 5,688 Stars、440 Forks。它的关键优势不是 Stars，也不是约 200 个模板，而是建立了一个高层信息图语法。

AI 生成的不是最终像素，也不是低层 SVG 坐标，而是一份人和模型都能读懂的 DSL：

infographic list-row-simple-horizontal-arrow
data
  lists
    - label Step 1
      desc Start

这份中间产物可以流式生成、实时渲染、人工修改、版本管理，并继续输出 SVG。AntV 还提供内置编辑器以及 Claude Code、Codex、Obsidian、Slidev、VS Code、Markdown 等生态集成。

Onepager 直接让模型生成 HTML/CSS，视觉自由度更高，但也把语义、布局、样式、渲染全部耦合进最终文件。修改一个信息关系，模型常常需要重新理解整份 HTML。AntV 的模板化视觉上限可能不如自由 HTML 海报，但它在可编辑性、生态和长期资产价值上已经领先一个产品代际。

2.4 正确路线不是放弃 HTML，而是在 HTML 前面增加 Onepager IR

Onepager 不需要复制 AntV 的全部 DSL，也不应该退化成模板渲染器。

更合理的架构是：

原始内容
  ↓
内容分析与事实包
  ↓
Onepager IR（语义、叙事、模块、证据、设计意图）
  ↓
布局配方与品牌约束
  ↓
HTML / SVG / PNG 渲染器

IR 可以是 JSON 或受约束的 YAML。它至少应该包含：

  • 核心论点；
  • 目标读者与传播场景；
  • 内容类型与逻辑关系；
  • 模块 ID、模块角色、文案和事实来源；
  • 数据值、单位、来源、是否允许改写；
  • 视觉优先级；
  • 建议图表类型；
  • 画布和品牌约束；
  • 锁定状态；
  • 渲染配方版本。

一旦有了 IR，“换风格”“换尺寸”“只改一个模块”“导出 SVG”“比较三个版本”“保存为配方”才会成为低成本动作。

三、纵向分析：Onepager 如何走到今天

3.1 第一阶段：先解决“能不能生成”

2026 年 3 月，项目以 OnePage Generator Skill 起步。早期提交大量集中在目录结构、命名、安装位置、展示图和基础风格。

这是典型的工具萌芽期：先证明 Agent 能把文字变成 HTML，再通过截图形成可分享图片。此时产品价值非常直接，用户提供内容，Skill 代替前端设计师完成单页。

这个阶段形成了两个后来一直保留的基因：

  1. HTML/CSS 是主要渲染媒介。
    它比图像模型更适合中文、长文字、精确数据和稳定布局。

  2. Skill 本身就是产品入口。
    用户不需要打开一个独立 SaaS，可以在 Claude Code、Trae 等环境里直接调用。

这两个选择今天仍然成立。问题在于，当能力持续增加，原本轻量的 Skill 开始承担内容策略、设计系统、渲染器、质检器和交付器等多重角色。

3.2 第二阶段：从排版工具升级成内容智能

2026 年 4 月，项目加入内容智能、类型差异化、视觉标准、质量检查、A4、BigNumber 开关、署名和文件命名。

这是 Onepager 最重要的一次产品跃迁。

它不再满足于“把输入排得好看”，而是试图回答“输入应该如何被重新组织”。T1 商业说服、T2 使用指南、T3 信息图、T4 宣传海报，本质上是四种不同的传播任务。

这次跃迁带来了真正的差异化，也埋下复杂度：

  • 内容类型影响模块必备项；
  • 密度影响改写和布局；
  • 风格影响字体、色彩、图标；
  • 画布影响信息容量；
  • BigNumber 又影响数据要求。

如果这些变量只存在于系统内部，它们是智能路由。如果全部交给用户，它们就是配置表单。

Onepager 当前正处于这个分岔点。

3.3 第三阶段：审美强化与规则膨胀

2026 年 5 月，项目加入 B9 Google Native、T4 海报、视觉放大器、设计意图声明和更细的交叉规则。

这一阶段明显提升了最终作品的视觉识别度，但 Git 历史也出现多次“原则化”“去模板化”“重新生成”“回滚”。这不是偶然。

海报设计存在一个难以完全形式化的矛盾：

  • 规则越具体，输出越稳定，但越容易模板化；
  • 原则越抽象，模型自由度越高，但结果越不稳定；
  • 示例越强，模型越容易模仿示例，而不是理解内容；
  • 风格选项越多，用户越容易认为产品价值就是“换皮肤”。

当前项目用大量文字规范试图同时获得稳定性与创造力，但缺少一个结构化中间层来划分“什么必须稳定，什么允许自由”。

应该稳定的是信息事实、叙事关系、模块角色、品牌边界和画布约束。

应该自由的是构图节奏、视觉隐喻、局部形式和艺术表达。

3.4 第四阶段：工程可靠性补课

最近一轮优化补充了配置 Schema、静态质检、浏览器渲染质检、fail-closed 截图、自动测试与 CI。

这一步非常重要，因为正式汇报、方案介绍和数据海报不能接受文字裁切、字体缺失、数据编造或尺寸错误。

但质量门禁只能保证产品“没有明显坏掉”，不能自动创造用户价值。下一阶段不应继续把主要精力放在新增检查项，而应让这些工程能力变成用户可感知的承诺：

  • 可复现；
  • 不编数据；
  • 输出前自动验证；
  • 同一源内容能稳定生成多尺寸版本；
  • 每个结果都带生成清单和证据状态；
  • 局部修改不会破坏已确认部分。

四、横向分析：同类产品分别赢在哪里

4.1 AntV Infographic：赢在中间语言与生态

AntV Infographic 是最重要的直接参照。它定位为“声明式信息图可视化引擎”，提供 AI 友好语法、约 200 个模板、主题系统、编辑器、流式渲染和 SVG 输出。

它的产品判断非常清楚：

AI 不应该直接画最终图，AI 应该生成一个稳定、可执行、可修改的信息结构。

它由此获得四个优势：

  1. 模型生成成本更低，DSL 比完整 HTML 更短；
  2. 错误更容易定位，不需要在几百行 CSS 里找问题；
  3. 人类可以修改结构文本；
  4. 社区可以围绕模板、主题、编辑器、插件和渲染器扩展。

其短板也明确：模板决定了表达边界。复杂海报、强品牌视觉、特殊中文构图和内容型叙事并不一定适合标准信息图模板。实际 Issues 中也出现模板不足、架构图需求、PNG 文本裁切和模板失败。

Onepager 不应该和 AntV 比模板数量。它应该在 AntV 不擅长的部分建立优势：

  • 单页整体叙事，而不是单个图形组件；
  • 中文高密度内容；
  • 商业说服、宣传海报等非纯图表任务；
  • 内容删改和表达策略；
  • 设计意图与品牌气质；
  • 输出前事实和几何质检。

同时，Onepager 完全可以把 AntV 作为内部图表渲染器，减少自己维护流程图、矩阵、层级图等基础组件的成本。

4.2 Madopic：赢在即时编辑

Madopic 约 206 Stars，产品路径简单：左侧写 Markdown，右侧实时预览，调整背景、字号、边距和模式，然后导出 PNG、PDF 或 HTML。

它支持 Mermaid、ECharts、KaTeX、代码块和图片，适合技术内容、学习笔记和学术表达。

Madopic 没有 Onepager 那么强的内容重构能力，但用户始终知道：

  • 当前源内容是什么；
  • 改一行会发生什么；
  • 导出前是什么样；
  • 哪些部分能自己控制。

Onepager 的自然语言交互更聪明，却更不透明。用户看不到模型如何理解内容，也看不到模块结构，直到最终 HTML 生成完。

应该借鉴的不是 Markdown 编辑器本身，而是连续反馈：内容结构、视觉草图、最终渲染不应该在最后一次性揭晓。

4.3 AI Infographic Generator：赢在完整生成工作台

这个项目 Stars 不高，但产品思路完整：

  • Claude 生成可编辑 HTML；
  • Gemini 生成视觉更自由的 PNG；
  • Haiku 将简单主题增强成结构化 brief；
  • 每次生成保存 HTML、PNG、Prompt、模型、Token 和成本；
  • 支持历史列表、网格比较、参考图、模型切换和多平台尺寸。

它最值得借鉴的是“每次生成都是一个可追溯项目”，而不是散落在目录里的两个文件。

Onepager 当前的 HTML 和 PNG 文件名可以避免覆盖，但没有标准 manifest，也没有历史浏览和版本关系。用户无法快速回答：

  • 这张图用了哪个配置；
  • 是从哪个源文件生成；
  • 上一版改了什么；
  • 哪个版本通过了哪些检查；
  • 这一版能否复现；
  • 如何基于它生成另一个尺寸。

4.4 Astra Graphic：赢在品牌和双引擎

Astra Graphic 把 AI 直出、HTML 精排版和混合模式拆成三条路线，并为客户维护 brand.json、CSS 和 AI 风格约束。

它的“28 万种组合”并不是值得照搬的产品表达。组合数很容易变成营销数字，不能代表真实质量。

真正值得借鉴的是：

  • 用户保存的是品牌，而不是每次重新选风格；
  • 图像模型负责氛围、插画、封面；
  • HTML 负责文字、数据和内容页；
  • 混合模式将两者组合；
  • 系统根据任务自动路由，用户可以覆盖。

Onepager 当前每次都要求选择 B1-B9。对高频用户而言，最常见的需求不是每次换一个风格，而是“永远保持我的品牌，只根据内容改变结构”。

4.5 Article Poster Generator：赢在单一场景

这个项目只有约 22 Stars，但一句话就能理解：

输入一篇长文章，自动拆成 5-8 张适合公众号、小红书、朋友圈的高清信息图海报。

它的能力不如 Onepager 泛化，产品价值却更容易传播。

Onepager 当前同时覆盖产品介绍、方案、指南、信息图、宣传海报、团队汇报、数据概览。每一项都成立，但合在一起后，用户很难形成具体心智。

开源产品早期更需要一个楔子，而不是一个完整能力地图。

4.6 Slidev、Marp 与 Mermaid：赢在源文件和生态

Slidev 约 48,005 Stars，Marp 约 12,317 Stars，Mermaid 约 89,630 Stars。它们的成功不来自一次性生成质量，而来自可积累的源文件和扩展生态。

用户可以把 Markdown 或 DSL：

  • 放进 Git；
  • 在编辑器里预览；
  • 在 CI 中批量构建；
  • 应用主题；
  • 嵌入文档；
  • 交给其他人继续修改；
  • 多年后重新生成。

Onepager 的 HTML 可以进 Git，但它不是理想源文件。它更像编译产物。

如果 Onepager 想从 Skill 变成产品，必须区分：

  • 源内容：用户事实与原始表达；
  • 视觉语义：Onepager IR；
  • 主题和配方：品牌、风格、布局能力；
  • 构建产物：HTML、SVG、PNG、PDF；
  • 构建记录：manifest 与质检报告。

五、产品设计深度诊断

5.1 目标用户尚未收敛

当前文档同时在服务四类人：

  1. 不会设计、只想快速出图的内容创作者；
  2. 需要正式汇报和方案交付的产品、咨询、管理人员；
  3. 想在 Agent 中自动化生成视觉内容的开发者；
  4. 对字体、网格、风格哲学有强偏好的设计型用户。

四类用户的产品要求不同。

内容创作者要快、要平台尺寸、要系列化。
商务用户要可信、要品牌、要数据来源、要可修改。
开发者要 CLI、Schema、批处理、可复现。
设计型用户要控制力、预览和细节调整。

当前 Onepager 用 A/B/C/T/E/F 将四类需求组织成一份渐进式配置协议。这套编码降低了自然语言确认成本，应当保留。需要优化的不是取消选择，而是让推荐理由更贴合当前内容，并把用户选择沉淀为可复用配置；高级用户缺少的仍是真正的局部控制。

建议选择一个主用户：

主用户：需要把复杂中文内容快速变成正式单页视觉的知识工作者和内容生产者。

开发者是分发渠道和扩展者，不是主交互对象。设计师不是主要替代目标。

5.2 价值主张需要从“风格多”转为“复杂内容讲清楚”

README 当前强调尺寸、九种风格、三种密度、四种类型、BigNumber 和图表。

这些是能力，不是价值。

更强的首页表达应该是：

把方案、报告和长文，压缩成一张讲得清、改得动、可直接发布的视觉单页。

下面再给三个承诺：

  1. 先读懂，再设计：自动提炼主线，不是把原文塞进模板；
  2. 事实不乱编：数字和来源可追溯，缺数据会明确提示；
  3. 结果可继续改：文案、结构、品牌和尺寸可以局部调整。

5.3 首次体验不应从六维菜单开始

推荐的新用户流程：

  1. 用户提供内容和一句用途；
  2. 系统分析受众、内容类型、密度和尺寸，形成推荐但不替用户决定；
  3. 先展示一份“内容蓝图”：
  4. 核心论点；
  5. 3-5 个模块；
  6. 将删除或压缩的内容；
  7. 缺失事实；
  8. 推荐视觉路径；
  9. 展示完整 A/B/C/T/E/F 菜单、推荐组合与逐项理由；
  10. 用户确认推荐，或覆盖任意一个或多个维度；
  11. 系统生成一个主方案和一个差异明显的备选；
  12. 用户在生成后做局部调整。

A/B/C/T/E/F 不是应被隐藏的专业参数，而是 Onepager 的核心交互语言。产品要做的是减少解释成本、保存用户选择并支持单维度修改。

默认体验要做到：

用户不需要理解设计理论，也能通过 A/B/C/T/E/F 菜单做出明确选择。

5.4 产品需要“内容蓝图”，而不只是设计意图

当前已有设计意图声明，但它发生在内容重构之后，且主要指导 CSS。

应该增加用户可见的内容蓝图：

goal: 让管理层理解为什么需要建设 AI Agent 平台
audience: 业务负责人
core_claim: Agent 平台的价值不是模型接入，而是可复用的业务执行能力
modules:
  - id: problem
    role: tension
    source_refs: [p2, p3]
  - id: solution
    role: answer
    source_refs: [p5]
  - id: evidence
    role: proof
    source_refs: [table1]
missing:
  - ROI 数据

它能让用户在花费生成成本前纠正理解错误，也能成为 IR 的第一部分。

5.5 “可编辑 HTML”不是足够的可编辑性

产品层面的可编辑应该包含：

  • 选中模块后修改文字；
  • 模块排序；
  • 模块锁定；
  • 选择替代布局；
  • 改变信息密度；
  • 切换品牌；
  • 将某个模块换成图表；
  • 只重生成选中区域；
  • 回到上一版本；
  • 对比两个版本。

近期不需要做完整 Canva 式画布。一个本地轻量预览器就足够：

  • 左侧 IR/YAML；
  • 中间实时画布；
  • 右侧属性；
  • 顶部版本与质检状态。

5.6 应优先建设品牌系统，而不是第十种风格

风格是一次性选择，品牌是持续资产。

建议新增：

{
  "brand": "zerox",
  "colors": {
    "background": "#ffffff",
    "text": "#202124",
    "accent": "#1a73e8"
  },
  "fonts": {
    "heading": ["Inter", "Noto Sans SC"],
    "body": ["Noto Sans SC"]
  },
  "logo": "assets/logo.svg",
  "rules": {
    "forbidden_colors": ["#6366f1"],
    "max_radius": 8,
    "tone": ["克制", "清晰", "可信"]
  }
}

首次创建品牌时让用户回答受众、品牌性格和审美方向，之后默认复用。

5.7 单页不是所有内容的正确答案

当前产品叫 Onepager，单页是重要边界。但输入可能远超一页容量。

产品应该明确三种结果：

  1. OnePage：单页摘要；
  2. Card Series：3-8 张社媒卡片；
  3. Visual Component：一个可插入 PPT/文章的信息图组件。

系统先判断内容容量。如果强行压成一页会丢失关键逻辑，应主动建议 Card Series，而不是降低字号或堆满卡片。

这不是产品扩张，而是对“一页边界”的诚实处理。

六、建议的产品架构

6.1 四层结构

第一层：Content Intelligence

  • 文档解析；
  • 事实与来源抽取；
  • 目标受众；
  • 叙事主线；
  • 内容压缩；
  • 信息结构识别；
  • 缺失数据提示。

第二层：Onepager IR

  • 稳定 Schema；
  • 模块 ID；
  • 内容和来源；
  • 视觉权重；
  • 锁定状态；
  • 设计意图；
  • 容量预算。

第三层：Recipe / Brand

  • 信息结构模板；
  • 画布配方；
  • 品牌；
  • 字体与资源；
  • 图表组件；
  • 版本和兼容性。

第四层：Renderer / Delivery

  • HTML + Playwright；
  • SVG；
  • PNG；
  • PDF；
  • manifest；
  • 质检报告。

6.2 不建议近期建设的能力

  • 完整自由拖拽白板；
  • 多人实时协作；
  • 大而全在线 SaaS；
  • 数百个低质量模板；
  • 独立模型托管平台；
  • 复杂数据 BI；
  • 完整 PPT 编辑器。

这些方向都会把产品拖进成熟平台的主战场。

七、优先级路线图

P0：把一次生成变成可复现项目

时间建议：2-4 周。

  1. 定义 Onepager IR v1；
  2. 每次生成输出 manifest.json；
  3. 保存源文件、IR、HTML、PNG、配置和质检结果；
  4. 支持 onepager rebuild manifest.json；
  5. 保留 A/B/C/T/E/F 六维菜单，并为每项提供内容相关的推荐理由；
  6. 增加用户可见内容蓝图；
  7. 给每个结果稳定项目目录和版本号。

验收指标：

  • 同一 manifest 重建结果视觉差异为零；
  • 新用户从输入到首图不超过 3 分钟；
  • 80% 用户能在一次交互内确认或修改 A/B/C/T/E/F；
  • 每个数据模块都能追溯来源或明确标记缺失。

P1：建立生成后局部迭代

时间建议：4-8 周。

  1. 模块稳定 ID；
  2. 锁定模块；
  3. 只改选中模块的文案、布局和密度；
  4. 版本 diff；
  5. 两个候选方向并排预览；
  6. 轻量本地预览器；
  7. 品牌配置文件和品牌向导。

验收指标：

  • 70% 修改不需要重生成整页；
  • 第二版生成时间低于第一版的 30%；
  • 品牌用户连续生成 10 张图时无需重复选择风格；
  • 用户能在不编辑 HTML 的情况下完成常见修改。

P2：扩展可编辑输出和生态

时间建议：8-12 周。

  1. SVG 渲染器或 AntV Infographic 组件集成；
  2. Recipe 包规范；
  3. 模板 gallery；
  4. npx skills 或通用 Skill 安装；
  5. CLI 批量构建；
  6. VS Code/浏览器预览；
  7. 社区贡献的截图回归和质量评分。

验收指标：

  • 至少 20 个高质量 Recipe，每个有适用场景和容量边界；
  • 支持 HTML/PNG/SVG 三种稳定输出；
  • 一条命令完成安装和环境检查；
  • 社区 Recipe PR 自动完成 Schema、渲染和视觉回归。

八、建议重写的产品叙事

当前叙事

多尺寸、九种风格、三种密度、四种内容类型、可选 BigNumber、智能图表和质量检查。

建议叙事

把复杂内容，编译成一张讲得清的视觉单页。

  • 先读懂：提炼结论、证据和叙事，不是套模板；
  • 不乱编：数据和来源可追溯；
  • 改得动：结构、文案、品牌和尺寸可以局部调整；
  • 出得稳：HTML、SVG、PNG 自动验证并可重复构建。

推荐首页 Demo

不要只展示一张最终海报。展示完整闭环：

原始长文
→ 内容蓝图
→ 两个设计候选
→ 用户说“锁住标题，把第二块换成对比”
→ 局部更新
→ PNG + SVG + manifest + PASS

这个 Demo 比九张不同风格的图更能说明产品价值。

九、横纵交汇：历史如何塑造了今天

Onepager 今天的优势和短板来自同一个历史选择：直接生成完整 HTML。

这个选择让它很早就获得了强视觉自由、中文精确文字和像素级布局，也让项目可以迅速吸收各种设计哲学。但每次新增能力，都继续以 Prompt、参考文档和 CSS 规则叠加。于是风格越丰富，规则越复杂，回滚越频繁。

AntV 从一开始选择 DSL，所以视觉自由受模板约束，却自然拥有编辑器、SVG、流式渲染和生态。Madopic 选择 Markdown，所以内容忠实但不主动重构。Astra 选择双引擎，所以可以在视觉自由和文字精确之间路由。

Onepager 不必否定自己的历史。它需要在现有 HTML 引擎前补上缺失的一层。

今天的内容智能，是 IR 的语义来源。
今天的交叉规则，是 Recipe 的原型。
今天的配置 Schema，是编译参数的开端。
今天的质量检查，是编译器诊断。
今天的 HTML 和 PNG，是构建产物。

把这些重新组织起来，Onepager 就不再是一份越来越长的 Skill Prompt，而是一套真正的视觉编译系统。

十、未来三个剧本

最可能剧本：成为小而强的 Agent Skill

项目继续优化内容理解、中文设计和可靠输出，在 Agent 用户中保持高口碑。它不会成为大型设计平台，但会成为“需要一张正式视觉单页时”的专业工具。

条件：降低首次配置摩擦，完善安装和案例，保持质量。

风险：缺少结构化资产和生成后编辑，用户偶尔使用，难以形成持续习惯。

最危险剧本：继续增加风格与规则

项目加入第十种风格、更多放大器、更多类型、更多例外。最终 Skill 越来越长，模型执行更不稳定，用户也无法理解产品边界。

此时 AntV、HTML Anything 或双引擎产品会在模板、编辑器、生态和工作台方面快速领先。Onepager 只剩“某些案例很好看”，但没有可复用的系统优势。

最乐观剧本：成为单页视觉编译器标准

Onepager 建立 IR、Recipe、Brand、Renderer 和 Manifest 五个稳定层。它可以作为 Skill、CLI、MCP 或本地预览器运行，并支持 HTML/SVG/PNG。

用户把方案、报告、会议纪要、研究文档交给它，它先生成可信内容蓝图，再输出可编辑视觉资产。社区贡献的不是随意 Prompt，而是带 Schema、适用边界和金标准截图的 Recipe。

它不和 Canva 比画布，不和 Slidev 比演示，不和 AntV 比模板数量。

它拥有一个更窄但更有价值的位置：

复杂内容到可信单页视觉资产的标准编译链。

十一、最终优化清单

立即做

  1. 重写 README 首屏价值主张；
  2. 保留 A/B/C/T/E/F 交互协议，强化逐项推荐、组合回复和单维度修改；
  3. 增加内容蓝图确认；
  4. 定义 IR v1；
  5. 输出 manifest；
  6. 保存项目目录与版本；
  7. 增加品牌配置；
  8. 为现有九种风格改名为“视觉方向”，避免用户把它理解为换皮。

随后做

  1. 模块 ID 与局部重生成；
  2. 锁定内容和布局；
  3. A/B 候选比较；
  4. 本地实时预览；
  5. SVG 输出或 AntV 组件集成；
  6. Recipe 规范与 Gallery；
  7. CLI 批量构建；
  8. Skill 安装与触发评测。

暂时不做

  1. 完整拖拽设计器；
  2. 多人实时协作；
  3. 大型在线 SaaS；
  4. 继续无边界增加风格；
  5. 用模板数量作为主要增长指标。

十二、北极星指标

不建议用“生成图片数量”作为唯一指标。它会鼓励一次性生成和无效重试。

建议北极星指标：

通过质检并被用户确认的可复用视觉项目数。

辅助指标：

  • 首次成功时间；
  • 首版确认率；
  • 平均重生成次数；
  • 局部修改占比；
  • 30 天内项目复用率；
  • 品牌复用次数；
  • 多尺寸派生率；
  • 事实缺失拦截数；
  • 构建 PASS 率；
  • Recipe 被重复使用次数。

十四、方法论说明

本报告使用横纵分析法：纵向追踪 Onepager 从模板生成、内容智能、审美规则到工程质控的演进；横向比较 AI 信息图、Markdown 视觉工具、Agent Skill、DSL/SVG 引擎和文本驱动视觉生态；最后将历史选择与当前竞争位置交叉，形成产品路线判断。
