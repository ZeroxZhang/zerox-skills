# 使用场景目录

本文件回答一个问题：**这次要做的是哪一种图？**

`S1-S6` 是 zerox-onepager 的第一道选择题。它不替代 `A/B/C/T/E/F`，而是先把"用在哪、给谁看、要达成什么"定下来，再自动带出一套默认配置。选对场景，后面五个维度基本可以照单接受；选错场景，后面怎么调都别扭。

> 机器可读事实源：`references/config-schema.json` 的 `scenes` 与 `scene_router`。

---

## 一分钟选型表

| 编号 | 场景 | 一句话判据 | 典型场合 | 默认配置 |
|:--|:--|:--|:--|:--|
| `S1` | **产品介绍** | 第一次看到的人，要在这一屏里决定"要不要了解你" | 官网首屏、产品手册封面、发布会单页、融资材料 | `A4 · B2 · C2 · T1/product · E1` |
| `S2` | **工作汇报** | 上级扫 30 秒就要能拍板 | 周会/月会材料、项目复盘、OKR 进度、跨部门同步 | `A2 · B7 · C3 · T3 · E1` |
| `S3` | **客户沟通** | 客户看完要能说出"你和别人有什么不一样" | 方案首页、投标单页、售前一页纸、续约材料 | `A2 · B9 · C2 · T1/solution · E1` |
| `S4` | **活动宣传** | 3 秒内让人想报名、想去、想转发 | 发布会海报、招募/招生、直播预告、社群推广 | `A4 · B5 · C1 · T4 · E2` |
| `S5` | **数据洞察** | 读者要能说出"这组数据最反常识的一点" | 行业报告单页、季度数据回顾、融资 BP 数据页 | `A2 · B7 · C3 · T3 · E1` |
| `S6` | **知识方法** | 读者第二天能照着做完第一步 | 方法论卡片、SOP 单页、课程讲义、团队新人包 | `A1 · B2 · C2 · T2/steps · E2` |

## 三条判据（选不出来时按顺序问）

1. **给谁看？** 自己人 → `S2`；客户 → `S3`；陌生人 → `S1` 或 `S4`
2. **想让 TA 看完做什么？** 做决策 → `S2`/`S5`；掏钱/合作 → `S3`；报名/到场 → `S4`；学会 → `S6`
3. **手上有多少内容？** 几句话 → `S4` 或 `S1`；一页材料 → `S3`/`S6`；一堆数据 → `S2`/`S5`

> 仍然说不清时，默认 `S2 工作汇报`。它是唯一强制"结论先行"的场景，几乎任何素材被它逼一遍都会浮出主线；之后再改 `S1`/`S3` 只需换语气，不用重做结构。

## S1 产品介绍

> **一句话**：让第一次看到的人在一屏内看懂：这是什么、解决谁的问题、凭什么信。

**谁在看 / 什么场合**
潜在用户、客户、投资人、刚入职的同事。场合通常是"没有人在旁边讲解"的自助阅读——官网首屏、产品手册、展台立牌、PDF 附件。

**这张图必须回答的四个问题**
1. 它是给谁用的？
2. 它替代或改善了什么旧的麻烦？
3. 凭什么相信（数字、案例、背书）？
4. 下一步做什么？

**内容骨架**（按顺序，缺一不可）

```
① 一句话价值主张（主语是用户，不是产品功能）
② 痛点 → 方案（左右对照最省篇幅）
③ 2-4 个可验证数字（BigNumber）
④ 能力/场景 2-3 条（每条一个动词开头）
⑤ 信任背书（客户、案例、认证、规模）
⑥ 单一 CTA
```

**默认配置**：`A4 · B2 · C2 · T1 + focus=product · E1`
**可替换**：内容多改 `A1`；想更现代改 `B9`；面向 C 端年轻用户改 `B10`。

**视觉建议**
- Hero 区必须有一个"产品是什么"的可视锚点（屏幕示意、结构图、场景照），不能纯文字开场
- 数字区（BigNumber）是第二视觉重心，字号要比所有标题大
- CTA 只出现一次，用强调色实心按钮，不要和正文抢

**什么时候不该选它**
- 你已经有一份完整的方案要讲 → 用 `S3`
- 内容其实是使用步骤 → 用 `S6`
- 目的是一天内拉报名 → 用 `S4`

**验收判据**
让一个不了解这个产品的人读 30 秒，然后复述：这是什么 + 为什么比旧的强。复述不出来 = 失败。

**标题写法对比**

| ❌ 坏 | ✅ 好 |
|:--|:--|
| 新一代智能数据平台 | 把 3 天的数据拉取，压成 10 分钟 |
| 全链路解决方案 | 从采集到看板，一个团队全包 |

## S2 工作汇报

> **一句话**：向上或平级讲清：结论是什么、支撑在哪、风险与下一步是什么。

**谁在看 / 什么场合**
上级、跨部门同事、项目干系人。场合是会议投屏或邮件附件，读者往往只有 30 秒注意力，且会带着"所以我要做什么"的心态看。

**这张图必须回答的四个问题**
1. 结论是什么（不是过程）？
2. 支撑这个结论的 3-5 个数据在哪？
3. 有什么风险、阻塞、需要协调的？
4. 下一步谁在什么时候做什么？

**内容骨架**

```
① 结论标题（一句话，含数字）
② 三个支撑点（每点一个数据）
③ 一组对比图（本期 vs 上期 / 目标 vs 实际）
④ 风险与阻塞（红色标注，不超过 3 条）
⑤ 下一步：责任人 + 时间 + 动作
```

**默认配置**：`A2 · B7 · C3 · T3 · E1`
**可替换**：要更沉稳改 `B1`；要更"公司通用"改 `B9`；内容少改 `A3`。

**视觉建议**
- 结论必须占据页面上最大的字，而不是"关于 XX 项目的汇报"
- 数据用 mono 字体，右对齐，让列可比
- 风险区用唯一一处强调色，其余全部中性——让风险自己跳出来
- 避免"时间轴式流水账"，那是日志不是汇报

**什么时候不该选它**
- 受众是外部客户 → 用 `S3`
- 内容是纯数据发现、没有行动建议 → 用 `S5`

**验收判据**
上级看完能直接说"行，按这个走"或"这里我要问一句"——而不是"你再多讲讲背景"。

**标题写法对比**

| ❌ 坏 | ✅ 好 |
|:--|:--|
| 2026 Q3 项目进展汇报 | Q3 提前 11 天交付，成本低于预算 7% |
| 用户增长分析 | 新增 42 万，但 7 日留存掉了 6 个点 |

## S3 客户沟通

> **一句话**：对一个具体客户说清：为什么选我、怎么做、多久见效、需要你配合什么。

**谁在看 / 什么场合**
客户决策人、采购、业务负责人。场合是售前提案、投标、续约谈判——读者带着"你和别人有什么不一样"和"我要承担什么风险"两个问题。

**这张图必须回答的五个问题**
1. 你听懂了我的问题吗？（复述客户原话最有说服力）
2. 你的做法和我现在的做法差在哪？
3. 有谁验证过？多久见效？
4. 需要我这边配合什么？
5. 下一步的具体动作？

**内容骨架**

```
① 复述客户的处境（用客户的语言，不夸饰）
② 核心判断（你对问题的诊断，这一句体现专业度）
③ 方案三步（做什么 → 交付物 → 时间）
④ 证据（同类客户结果、量化收益）
⑤ 客户侧需要配合的事项（降低对方的决策风险）
⑥ 下一步 + 联系人
```

**默认配置**：`A2 · B9 · C2 · T1 + focus=solution · E1`
**可替换**：要更"高端克制"改 `B6`；要更"权威精确"改 `B2`；要竖版发微信改 `A4`。

**视觉建议**
- 语气克制胜于华丽：这一页的目标是"可信"，不是"惊艳"
- 把"客户的原话"做成引文块，是最快建立信任的视觉手法
- 时间轴/交付节奏图必须真实可交付，不写"尽快"
- 少用感叹号和"赋能/闭环"这类词，会让客户警惕

**什么时候不该选它**
- 还没见过客户、只是公开宣传 → 用 `S1`
- 客户已经签约，这是内部汇报 → 用 `S2`

**验收判据**
客户能用自己的话复述出"你和他人的差异化在哪"，并且能指出下一步要做什么。

**标题写法对比**

| ❌ 坏 | ✅ 好 |
|:--|:--|
| 为 XX 客户提供数字化解决方案 | 把你们 3 套系统的对账，收到一张表里 |
| 我们赋能企业增长 | 上线后第 8 周，对账人力从 4 人降到 1 人 |

## S4 活动宣传

> **一句话**：让人在 3 秒内产生「我要去 / 我要报名 / 我要用」的冲动。

**谁在看 / 什么场合**
潜在参与者、社交媒体刷到的人。场合是朋友圈、社群、海报墙、电梯屏——读者平均只给 1-3 秒，而且是"滑过去"而不是"读进去"。

**这张图必须回答的四个问题**
1. 这是什么活动（一眼可辨）？
2. 什么时候、在哪（或哪个链接）？
3. 为什么值得去（一句话钩子）？
4. 怎么参加（一个动作）？

**内容骨架**

```
① 巨型主视觉（一个元素占 40% 以上面积：巨字 / 满铺色块 / 强对比图形）
② 一句钩子（≤ 12 字，能被复述）
③ 时间 · 地点 · 形式（mono 元信息，一行内）
④ 一个 CTA（二维码或短链）
⑤ 极小字补充（主办方、署名）
```

**默认配置**：`A4 · B5 · C1 · T4 · E2`
**可替换**：要更酷改 `B8`；要短视频质感改 `B10`；要更"官方活动"改 `B9`（自动 Poster 模式）；方形发朋友圈改 `A3`。

**视觉建议**
- 这一场景是唯一允许"信息不全"的：海报的失败原因几乎都是信息太多
- 强制 `P1` 巨型字号，最大字与最小字比 ≥ 10:1
- 主视觉只能有一个；出现第二个争夺注意力的元素就删掉
- CTA 用反色或满铺色块，其余全部让位

**什么时候不该选它**
- 你需要解释清楚一个复杂产品 → 用 `S1`
- 活动已经结束，这是复盘 → 用 `S2`

**验收判据**
把页面缩到手机缩略图大小，仍能读出"是什么活动 + 什么时候"。

**标题写法对比**

| ❌ 坏 | ✅ 好 |
|:--|:--|
| 2026 年度用户大会诚邀莅临 | 11.28 上海，300 个座位 |
| 第五届行业创新峰会 | 这一次，聊聊失败 |

## S5 数据洞察

> **一句话**：用一组数据讲清一个结论，让人看见「原来如此」。

**谁在看 / 什么场合**
分析师、业务负责人、行业读者。场合是报告中间页、数据周报、BP 数据章节——读者已经相信数据，缺的是"所以呢"。

**这张图必须回答的四个问题**
1. 结论是什么（一句话，且不是数据的复述）？
2. 口径是什么（时间、范围、样本）？
3. 对比是什么（和谁比、和什么时候比）？
4. 有什么反常识或异常？

**内容骨架**

```
① 结论句（含关键数字）
② BigNumber 2-3 个（口径注释紧跟其下）
③ 一张主图（只讲一件事，不要多系列堆叠）
④ 一个反常识发现（这是本场景的价值所在）
⑤ 来源与口径
```

**默认配置**：`A2 · B7 · C3 · T3 · E1`
**可替换**：要更暗色科技改 `B1`；要更公开报告感改 `B9`；单点数据改 `A3`。

**视觉建议**
- 图表直接标注结论，不要让人自己看图例推
- 一个图表只回答一个问题；需要多问题就分成多图，不要叠双 Y 轴
- 网格线极淡、数据线极重，形成"数据浮起来"的效果
- 禁用饼图超过 4 个扇区；禁用 3D 效果

**什么时候不该选它**
- 数据只是佐证、真正要讲的是方案 → 用 `S3`
- 数据服务于内部决策、需要行动建议 → 用 `S2`

**验收判据**
读者能指着图说出"最反常识的一点是什么"，而不是"数据挺多的"。

## S6 知识方法

> **一句话**：把一套做法拆成别人能照着执行的步骤或卡片。

**谁在看 / 什么场合**
学习者、团队新人、社群成员。场合是收藏转发、入职材料、课程配套——读者的核心动作是"保存下来以后用"。

**这张图必须回答的四个问题**
1. 方法解决什么问题？
2. 分几步？每步的输入和输出是什么？
3. 哪一步最容易做错？
4. 做完怎么判断成功？

**内容骨架**

```
① 方法名 + 适用场景（一句话）
② 3-7 个编号步骤（每步：做什么 + 产出什么）
③ 每步的关键提示或判断标准
④ 常见坑 1-3 条（这是可信度的来源）
⑤ 一页可带走的总结句
```

**默认配置**：`A1 · B2 · C2 · T2 + focus=steps · E2`
**可替换**：要东方留白改 `B6`；要通用企业感改 `B9`；方形卡片改 `A3`。

**视觉建议**
- 步骤编号用 mono 大号数字，形成纵向节奏
- 流程用纵向而非横向（手机上更好读），横向仅 `A2` 使用
- 每步等宽对齐，但允许"重点步骤"占两倍高度——节奏优于均分
- 关键提示用细边框或左侧色条，不要用图标堆砌

**什么时候不该选它**
- 内容本质是卖东西 → 用 `S1`
- 内容本质是证明结论 → 用 `S5`

**验收判据**
读者第二天能不看原文就完成第一步。

## 同一份素材，三种场景，三种完全不同的图

假设素材是："我们的 AI 客服产品，接入 2 小时，回答准确率 92%，已服务 120 家企业，平均节省 40% 人力。"

| 场景 | 标题会怎么写 | 首屏放什么 | 主体结构 | 页面气质 |
|:--|:--|:--|:--|:--|
| `S1` 产品介绍 | 把客服人力成本压掉四成 | 一句话价值主张 + 92% 大数字 | 痛点→方案→能力→背书 | 明亮、自信、面向陌生人 |
| `S2` 工作汇报 | 客服 AI 上线三个月，人力下降 41% | 结论句 + 期初/期末对比 | 支撑数据→风险→下一步 | 冷静、密集、面向决策 |
| `S3` 客户沟通 | 你们现在 12 个人接的电话，3 个人就够了 | 客户处境复述 | 诊断→三步方案→同类案例→配合事项 | 克制、可信、面向一个具体的人 |

同一批事实，结论、语气、顺序、视觉重心全部不同。**这就是为什么必须先选场景**：场景决定的是"这一页在替谁说话"。

## 场景 × 其他维度的联动规则

1. **场景优先于风格**：先 `S`，再 `B`。用户先说了"要暗黑风"，也要回到"给谁看"再定 `S`。
2. **场景决定默认值，不锁死**：`config-schema.json` 里的 `defaults` 只是推荐；用户改任何一个维度都以用户为准。
3. **场景与类型冲突时，以场景为准**：`S4` 选了 `T1`（商业说服）是矛盾的——海报装不进产品说明。此时提示用户改 `T4` 或改场景。
4. **场景影响 BigNumber 的必要性**：`S2`/`S5` 天然需要数字，缺数据应回问用户而不是切 `E2`；`S4` 天然不需要，默认 `E2`。
5. **一次只服务一个场景**：一张图同时给"内部汇报 + 对外宣传"，必然两头不讨好。拆成两张。
