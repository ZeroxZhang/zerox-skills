# 原始材料存档规范

网页会消失、会被改写。读到即存下，结论才能离线追溯。本文是研究包原始层的完整规范。

## 1. 存什么

**必存：**

- 全部检索日志
- 所有读过且判定相关的来源（无论最终是否被引用）
- 追溯到的一手出处
- 反面证据
- 用户提供的材料
- 报告用到的数据文件与图表原图

**只记日志、不存全文：** 打开后判定无关、低质或重复的来源——在检索日志里记下 URL 和弃用原因即可，不占体积。

**用户要求精简时**：只存被引用的来源和检索日志，并在 README 的统计里说明「按用户要求精简」。

## 2. 分层与只读

| 层 | 目录 | 角色 | 可改性 |
|---|---|---|---|
| 原始层 | `raw/` | 来源原文、原始文件、检索日志、用户材料 | **采集后不改正文** |
| 加工层 | `notes/`、`analysis/` | 证据笔记、计算与派生数据 | 可改，更正写在这里 |
| 结论层 | `report.md` | 最终报告 | 综合阶段产出 |

更正与解读**只写在加工层**，不许回头改 `raw/`。来源内容更新后需要重新采集时：分配新 ID，用元数据 `supersedes` 指向旧 ID，**旧版保留**——一个 ID 永远对应一份不变的快照。

为什么这样设计：长任务会碰到上下文截断或压缩。计划和证据必须落盘，否则中途恢复时只能凭记忆「补存」原文，那等于编造。研究包因此可以中断后恢复：存在 `plan.md`、`sources.md` 和检索日志时，先读它们再从断点继续。

## 3. 采集方式与完整度

按优先级选择，实际用的方式记入快照 `capture_method`：

| 优先 | 采集方式 | 做法 | 适用 |
|---|---|---|---|
| ① | `script` | 脚本直接下载原始字节到 `raw/files/`，正文提取成 Markdown 快照，算 SHA-256 | 默认。能执行代码时**必须**先用脚本，保证读到的就是存下的 |
| ② | `browser` | 需要渲染的动态页面、图表、社交媒体帖，另存截图或打印 PDF | 脚本拿不到完整渲染结果时 |
| ③ | `fetch-tool` | 只能拿到抓取工具返回的文本时，由模型**逐字**写入快照 | 没有脚本或脚本被拒时 |
| ④ | `snippet` | 只有搜索结果摘要 | 仅当无法打开原文，且该线索仍值得记录 |
| ⑤ | `metadata-only` | 付费墙、需要登录、已失效：只存元数据和原因 | 不可访问时 |

**降级规则：**

- 脚本被拒（401/402/403/429、超时）时，可以改用抓取工具或浏览器正常访问。
- 遇到付费墙、登录或验证码**就停止**，按 ⑤ 处理。**不绕过**任何访问限制。
- 若抓取工具返回的是**模型处理过的摘要**而非原文（例如某些 WebFetch 实现会先用小模型按提示词处理页面），完整度标 `summary`——这种快照不能作为逐字摘录的依据，应改用脚本或浏览器获取原文。
- ③ 逐字转写时**不得改写、概括或补全**。篇幅过长时至少完整保存与研究相关的段落（带上下文），删节处标 `[...]`，完整度标 `partial`。

**完整度等级**（从高到低，写入快照 `completeness` 与 `sources.md`）：

`full` > `partial` > `summary` > `snippet-only` > `metadata-only`

`summary` 及以下**不能单独支撑关键结论**。

**公开存档（Wayback Machine 等）**：可以查已有快照并记录 `archive_url`；**不主动向公开存档服务提交链接**，以免暴露研究意图。

## 4. 来源 ID 与命名

- **ID = 代号 + 三位序号**：`M001` 主线程，`A001`/`B001`… 各研究线，`U001` 用户材料。串行执行时全部用 `M`。
- **文件名 = `<ID>-<slug>`**，slug 用小写英文或拼音加连字符，不超过 40 字符。
- 同一来源的多个文件共用前缀：`A003-xxx.md`、`A003-xxx.pdf`、`A003-xxx-01.png`。
- 中断后续跑时，每个前缀从**现有最大序号往后编**，不复用、不留空洞。
- 子代理用自己的代号作前缀，避免并行冲突；主线程合并时做去重。

## 5. 快照与元数据

快照文件 = YAML 元数据头 + 正文，模板见 `../assets/snapshot-template.md`。必填字段：

| 字段 | 说明 |
|---|---|
| `id` | 来源 ID |
| `title` | 标题，保留原文语言 |
| `url` / `final_url` | 发现时的 URL / 重定向后实际落地 URL |
| `author_org` | 作者或机构，未知写 `unknown` |
| `published` | 发布日期，未知写 `unknown` |
| `accessed` | ISO 8601 带时区 |
| `language` | 语言 |
| `source_type` | `primary` / `secondary` / `tertiary` |
| `credibility` | `A` / `B` / `C`（用户材料写 `—`） |
| `conflict_of_interest` | `none` 或具体利益冲突 |
| `capture_method` | `script` / `browser` / `fetch-tool` / `snippet` / `metadata-only` |
| `completeness` | 五级之一 |
| `original_files` | 原始文件相对路径列表 |
| `sha256` | 原始文件哈希，无原始文件写 `null` |
| `research_line` | 所属研究线代号 |
| `subquestions` | 关联的子问题编号 |
| `supersedes` | 被取代的旧来源 ID，无则 `null` |
| `archive_url` | 公开存档链接，无则 `null` |
| `access_note` | 付费墙、截断、动态内容、脚本被拒改用浏览器等 |
| `rights_note` | 版权与使用限制，无则 `none` |

正文保留标题层级、列表和表格；PDF 保留页码标记（`<!-- p.12 -->`）；音视频文字稿保留时间戳。

## 6. 定位规范

`notes/` 里每条摘录都写定位（章节 / 段落、页码、表号、时间戳），让人**几秒内**就能在快照里找到原文。定位写法示例：

- `§3.2 第 4 段`
- `p.12 表 2`
- `00:14:32`
- `回复 #2453 的第 2 段`

## 7. 阈值

| 阈值 | 默认值 | 处理 |
|---|---|---|
| 单文件体积 | 50MB | 不下载，只登记链接和大小 |
| 研究包总体积 | 500MB | 暂停，询问用户（精简范围 / 换压缩 / 接受体积） |

阈值可按 brief.md 的约束调整；调整要在「方法与局限」里说明。

## 8. 用户材料

- 默认把原件副本放进 `raw/user-provided/`，登记 `U` 系列 ID。
- 需要时在 `raw/sources/` 生成文本快照（例如 PDF 需要页码定位时）。
- 文件过大或用户不希望复制时，只登记路径和哈希，并在 `sources.md` 备注「未复制」。
- 内部资料在元数据与 README 标注**「内部」**；不把其中的机密信息写进公开检索查询。

## 9. 索引维护

- `sources.md` 由**主线程**维护，内容以各快照的元数据头为准；两者不一致时**改索引去对齐快照**，不反向改快照。
- 子代理不直接改 `sources.md`（并行写入会冲突），只回传来源 ID 清单。
- 主线程每轮合并时做去重：同一 URL 且内容一致，或哈希相同的，只保留一个规范 ID，其余标「重复→规范 ID」；同一 URL 但内容已变的，按新版本处理（新 ID + `supersedes`）。

## 10. 各类来源的处理示例

| 来源类型 | 首选 | 退而求其次 | 快照要点 |
|---|---|---|---|
| 普通网页 / 博客 | `script` 下载 HTML + 抽正文 | 浏览器另存 / 打印 PDF | 保留标题层级；记录 `final_url` |
| PDF 报告 / 论文 | `script` 下载 PDF 到 `raw/files/`，抽文本 | 浏览器打印 PDF | 正文加 `<!-- p.N -->` 页码标记 |
| 数据集 / CSV / XLSX | `script` 原样下载 | 记录来源与字段说明 | 原始文件进 `raw/files/`；算式进 `analysis/` |
| 官方文件 / 标准 | `script` 下载原文 | 浏览器 PDF | 条文号写进定位；注意修订版本 |
| 社交媒体帖 | 浏览器截图或打印 PDF | 逐字转写 + `partial` | 保留发布时间、作者、互动数据的时点 |
| 音视频 / 播客 | 官方文字稿 | 逐字转写 | 保留时间戳；注明转写来源 |
| 动态渲染页（图表、看板） | 浏览器截图 + PDF | 抓取工具取静态文本 | 截图存 `raw/files/`；快照记「动态渲染」 |
| 付费墙 / 登录墙 | — | — | 只存元数据 + `metadata-only`；查 Wayback 已有存档并记 `archive_url` |
| 搜索结果摘要 | — | — | `snippet-only`；必须在检索日志说明为何打不开原文 |

## 11. 工具

- `scripts/capture_source.py`：输入 URL 或本地路径 + 来源 ID + slug，下载原始文件、算哈希、抽正文、生成快照、输出一行 JSON 摘要。只用标准库即可运行，装了 `trafilatura` / `pypdf` / `beautifulsoup4` 时自动增强。遇到 401/403、付费墙、验证码或超过体积阈值时报错退出，**不做任何绕过**。
- `scripts/check_package.py`：交付前检查证据链完整性、摘录可追溯、元数据与哈希、孤立文件，并输出统计与 `manifest-sha256.txt`。
- 没有脚本或无法执行代码时，整个流程也必须能手动完成——手动按本文的字段清单逐项填。
