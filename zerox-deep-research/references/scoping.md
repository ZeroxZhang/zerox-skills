# 开题与定级

研究的价值在开题时就决定了一大半。本文给出定级判据、七类研究的子问题骨架、澄清问题库（附默认选项）与好坏开题对比。

## 1. 定级标准

| 级别 | 适用 | 投入 | 交付 |
|---|---|---|---|
| L1 快速 | 单一事实、定义、查数 | 3–10 次工具调用 | 简短回答 + 来源。默认不建研究包；用户要求留档时建只含 `raw/` 与 `answer.md` 的简化包 |
| L2 标准 | 聚焦的专题或对比 | 2–4 条并行研究线，每条约 10–15 次工具调用 | 完整研究包 |
| L3 深度 | 宽泛、多维、高风险决策 | 5 条以上研究线（复杂可超 10），多轮迭代 | 完整研究包 |

判断启发式：

- 一句话的可验证事实就能回答 → L1。
- 需要 2–3 个维度比较、单一领域内收得住 → L2。
- 跨领域、要支撑不可逆决策、用户要「全面」却没给边界 → L3。
- 拿不准就往高一级定，再用范围排除项收窄；但简单问题不要为了「显得专业」过度投入。
- 用户说了优先级（「先给我个大概」/「这次要下重注」）时以用户为准，并在 work/brief.md 记下。

## 2. 研究类型判定

先判断类型再套骨架——类型错了，子问题就会问偏。

| 类型 | 典型问法 | 核心交付 |
|---|---|---|
| 全景 | 「X 领域现在什么格局」 | 格局 → 驱动因素 → 产业链 → 趋势 |
| 对比选型 | 「A / B / C 哪个适合我们」 | 评估维度 + 对比矩阵 + 分场景结论 |
| 技术深潜 | 「X 的原理、瓶颈、代价」 | 机制 → 证据 → 适用边界 |
| 尽调 | 「这家公司 / 这个人靠不靠谱」 | 业务事实 + 风险信号 |
| 文献综述 | 「关于 X 学界怎么说」 | 共识 / 争议 / 研究空白 |
| 政策法规 | 「新规对我们有什么影响」 | 条文 + 生效时间 + 影响 + 待专业人士确认 |
| 事实核查 | 「X 这个说法是真的吗」 | 结论评级 + 证据链 |

混合类型（如「技术选型 + 尽调供应商」）以**主决策**定类型，另一类的骨架作为补充维度，不要并列开两条互不相干的主线。

## 3. 子问题骨架（七类）

以下每类给 4–6 个起手子问题。落地时按 brief 的决策用途增删，并按「对决策的影响 × 当前不确定性」排优先级。

### 全景

1. 市场/领域的当前规模、增速与口径是什么？谁在统计、彼此差多少？
2. 格局：主要参与者分几类，各自靠什么立足？
3. 上下游链条：价值在哪一段产生、被谁拿走？
4. 驱动因素与抑制因素：哪些变量会改变格局？
5. 技术/政策/需求侧的拐点信号：哪些变化已经在发生？
6. 未来 1–3 年的可验证情景，以及各情景的观测指标？

### 对比选型

1. 选型要支撑什么动作？上生产、试点还是淘汰现有方案？
2. 评估维度从哪里来（用户业务约束 > 通用榜单 > 供应商话术）？权重谁定？
3. 各候选在每个维度上的**实测/一手证据**（不是宣传口径）是什么？
4. 隐藏成本：迁移、运维、锁定、合规、退出。
5. 分场景结论：什么条件下选 A，什么条件下选 B？
6. 哪些维度上证据不足，需要用户自己试？

### 技术深潜

1. 机制：它到底怎么工作？关键假设是什么？
2. 什么条件下有效，什么条件下失效？边界在哪？
3. 代价：计算/经济/组织成本的量级与口径？
4. 与替代方案的对比：为什么不是别的做法？
5. 可复现性：有没有独立复现、基准、失败案例？
6. 前沿进展与未解决问题。

### 尽调

1. 主体做什么、靠什么赚钱、现金流从哪来？
2. 公开可验证的事实：注册、股权、财务、法律纠纷、监管记录。
3. 管理层/创始人的公开言论与实际成绩是否一致？
4. 客户、供应商、离职员工等多方口径是否互相印证？
5. 风险信号清单：关联交易、频繁换审计、诉讼、口碑、竞对评价。
6. 什么样的新证据会推翻「可投 / 可合作」的判断？

### 文献综述

1. 研问题是什么？主要理论脉络与代表作？
2. 共识：哪些结论被多个独立团队重复验证？
3. 争议：分歧点在哪、为什么分歧（数据、方法、定义、立场）？
4. 研究空白：哪些问题没人做或做得薄？
5. 方法学问题：样本、测量、外推边界。
6. 最近 2–3 年的增量与方向变化。

### 政策法规

1. 条文原文说了什么？关键定义与适用范围？
2. 生效时间、过渡期、溯及力？
3. 对目标对象的具体影响：义务、成本、机会？
4. 执法口径与已知案例：官方怎么解释？
5. 与既有法规的关系：冲突、替代、补充？
6. 需要向专业人士（律师/会计师/监管）确认的问题清单。

### 事实核查

1. 主张的精确表述是什么？可证伪的版本是什么？
2. 最早出处在哪？传播链上被改写了什么？
3. 支持证据：一手来源还是转引？有多少独立来源？
4. 反面证据与已知反驳。
5. 数字口径：时间、范围、分母、单位是否被偷换？
6. 结论评级（真 / 大致真 / 存疑 / 大致假 / 假 / 无法判定）+ 依据。

## 4. 澄清问题库

只问**会实质改变研究方向**的问题，一次问完，通常 1–3 个，最多 5 个。每个问题必须附默认假设或选项，让用户一句话就能回复（「按默认」）。

| 问什么 | 为什么值得问 | 可直接用的默认选项 |
|---|---|---|
| 用途与决策 | 决定深浅与结论口径 | 默认：支撑一次内部方案讨论，不做最终决策 |
| 受众 | 决定术语密度与结论先行程度 | 默认：熟悉业务但不熟悉该领域的内部同事 |
| 范围（时间） | 时效性话题不给边界就会跑偏 | 默认：近 3 年，重点近 12 个月 |
| 范围（地域/细分） | 「全球」和「国内」是两个研究 | 默认：中国大陆为主，海外作对照 |
| 包含与排除 | 防止研究面无限扩大 | 默认：只研究直接影响决策的环节，不做泛泛综述 |
| 已知信息与已有倾向 | 避免重复研究、也避免顺着倾向找证据 | 默认：按用户已提供的材料起步，不预设结论 |
| 交付形式与篇幅 | 决定综合深度 | 默认：Markdown 报告 + 完整研究包，正文 3000–6000 字 |
| 信源偏好与禁区 | 有些行业数据只在付费源里 | 默认：公开可得来源，不用无法存档的付费墙内容 |
| 时限 | 决定定级与是否并行 | 默认：一次会话内完成 L2 |
| 内部资料能否入包 | 涉密材料不能随手存档 | 默认：可入包但标注「内部」，对外分发前需删除 |

**不能提问的情形**：用户说「直接开始 / 别问我」，或处于非交互环境——把假设明确写进 work/brief.md 的「已采纳的假设」，并在最终报告的「方法与局限」逐条复述。宁可让人看到假设，也不要静默猜测。

## 5. 好坏开题对比

### 坏开题

> 核心问题：研究 AI 眼镜。
>
> 子问题：1. AI 眼镜是什么 2. AI 眼镜的技术 3. AI 眼镜的应用 4. AI 眼镜的未来

问题宽到无法证伪；子问题不是子问题是目录；没有决策用途；没有范围；没有证据要求。

### 好开题

> 核心问题：如果要在 2027 年推出一款面向开发者的 AI 眼镜，当前的技术成熟度与主要风险是什么？
>
> | # | 子问题 | 影响 | 不确定 | 优先级 | 需要什么证据 |
> |---|---|---|---|---|---|
> | Q1 | 光学显示方案（光波导 / Micro-OLED）的量产良率与成本区间 | 高 | 高 | P0 | 供应链一手访谈 + 两家以上机构测算 |
> | Q2 | 现有产品的日活与退货率（不是出货量） | 高 | 高 | P0 | 厂商财报口径 + 电商评论实测抽样 |
> | Q3 | 开发者生态的现存工具链缺口 | 中 | 中 | P1 | 主流 SDK 文档 + 开发者论坛实际反馈 |

差别在于：写清了用途与决策、每个子问题可证伪、指定了证据形态、标了优先级。
