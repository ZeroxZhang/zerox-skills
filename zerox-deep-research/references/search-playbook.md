## 1. 查询构造：先广后窄

模型天性爱写又长又细的查询（「2025 年中国向量数据库选型对比 最佳实践 企业级」），这类查询命中面窄、几乎必然漏掉权威综述。主动纠正：

1. **先摸图**：用 2–5 个词的短查询找综述、行业报告、官方概览、维基/百科条目当「地图」。
2. **读图定词**：从地图里拎出领域术语、机构名、产品名、标准号、英文原名。
3. **再收窄**：用精确术语 + 限定词（年份、site:、文件类型）追具体证据。
4. **最后查反面**：见 [对抗性检索](#5-对抗性检索)。

每轮顺序固定：短宽 → 术语 → 精确 → 反面。跳过第一步直接精确检索，是研究漏维度的头号原因。

## 2. 改写与同义扩展

同一个事实往往有多种叫法。每个子问题至少试 3 种表述：

- 中英对照：「向量数据库 / vector database / embedding database / vector search」
- 行业黑话与正式名：「大模型 / LLM / 基础模型 / foundation model」
- 角度变换：「X 优势」→「X 劣势」「X 替代」「X 失败案例」「X 争议」
- 主体变换：「厂商说法」→「用户抱怨」「第三方评测」「监管通报」
- 时间变换：加「2025 / 2026」「最新 / 现状 / 趋势」；找历史事实时反着加年份

**查询日志必须记录实际执行的原样**，不要事后再润色——改写轨迹本身就是「试过哪些方法」的证据。

## 3. 多语种检索

- 至少中英文各搜一轮。技术、金融、医药领域英文一手来源往往更全；政策、市场数据中文更贴近实际。
- 中文检索注意：官方文件用「全称 + 文号」；行业数据看口径（「出货量 / 销量 / 激活量」「市场规模是出厂价还是零售价」）。
- 英文检索注意：同一概念的美式/英式拼写（optimization / optimisation）、缩写全称。
- 非中英文领域（如日韩市场、欧盟法规），用英文检索 + 官方原文语言核对，不靠二手转述。

## 4. 一手来源定位

二手来源用来**发现线索**，关键事实要追到一手出处：

| 事实类型 | 一手出处 |
|---|---|
| 产品能力 / API / 价格 | 官方文档、官方定价页、发行说明 |
| 公司经营 / 财务 | 财报、年报、监管披露、招股书 |
| 政策法规 | 政府公报、条文原文、官方解读与答记者问 |
| 学术结论 | 论文原文（含补充材料）、预印本、数据集 |
| 市场数据 | 统计局、行业协会、原始调查报告（看样本与方法） |
| 人物观点 | 采访原文、演讲实录、财报电话会记录 |
| 技术参数 | 规格书、基准测试脚本、可复现实验 |

追溯方法：在二手文章里找脚注、链接、引号内的原话、报告名称，再直接检索那个原始对象。找不到一手出处时，把该事实的置信度降一档，并在 notes 里写明「仅二手转述」。

## 5. 对抗性检索

每条主要结论都要专门找反面证据，这是防止「研究得很顺但结论是错的」的唯一硬手段。

固定句式：

- 「X 问题 / 争议 / 失败 / 局限 / 批评」
- 「X vs 替代方案」
- 「X 被高估 / 被证伪 / 后来怎么了」
- 「X 安全事故 / 召回 / 处罚 / 破产」
- site: 负面信源（消费者投诉、监管通报、学术批评）

反面证据**同样存档**，并在 notes 里给反方观点最有力的表述（steelman），不许用稻草人版本糊弄过去。

## 6. 检索日志

每次检索**立即**写入 `work/search-logs/<代号>.md`，格式见 `../assets/search-log-template.md`。必填：

- 时间（ISO 8601 带时区）、工具名
- 查询原文（按实际执行的原样）
- 过滤条件（时间、语言、站点、文件类型）
- 看过哪些结果、打开了哪些（对应来源 ID）
- 弃用了哪些、为什么（无关 / 低质 / 重复→规范 ID / 只有摘要）

不要攒到一轮结束补记：补记会丢掉查询原文与弃用理由，事后无法证明「试过哪些方法」。中断续跑时接着往同一文件追加，从现有最大序号往后编来源 ID。

## 7. 停止规则

满足任一条即停：

- 所有子问题都达到 work/brief.md 要求的置信度
- 信息饱和：连续两轮的新来源没带来实质新信息
- 再研究也不太可能改变结论
- 预算用尽（work/brief.md 的工具调用/时间上限）

**不为不存在的信息无限搜索**：同一条信息换了 3–5 种策略（换语言、换术语、换主体、追一手、查存档）还找不到，就记为「信息缺口」，写明试过哪些方法（检索日志可佐证），继续推进其他子问题。

以下情形**暂停并问用户**，不要自行决定：

- 研究前提有误（比如用户以为的市场规模口径和行业通行口径不同）
- 范围需要大改
- 关键信息只在付费 / 受限来源里
- 研究包体积将超过 500MB
