## 1. 检查清单

**先跑脚本**：`python scripts/check_package.py <研究包>`。脚本查证据链、摘录可追溯、元数据与哈希、孤立文件。脚本输出实际文件数、解析量、摘录检查量、数据记录和报告数据关联量；任何格式失败或零覆盖不能视作通过。下面是必须人工判断的部分。发现问题**先改再交付**。

### 问题是否被回答

- [ ] 核心问题有直接回答吗（执行摘要第一段就能读到）？
- [ ] 每个子问题都回答了吗？没回答的是否已列进「未解问题」？
- [ ] 交付物符合 work/brief.md 的规格（格式、篇幅、文件名）吗？

### 事实与引用

- [ ] 数字、日期、名称与来源逐项一致？（重点查报告里手写过的数字）
- [ ] 每条非常识性事实都有引用？常识性陈述没被滥用成免检通道？
- [ ] **关键结论逐条回查快照原文**：引用确实支撑该论断，不是「看起来差不多」？
- [ ] 引用没被夸大：来源说的是「相关」，报告没写成「导致」？
- [ ] 绝无编造：来源、URL、原文摘录都能在快照里找到？

### 证据质量

- [ ] 关键结论建立在一手或权威来源上？
- [ ] 循环引用排掉了？（多处转引同源只算 1 个）
- [ ] 数字口径、单位、时间点、统计方法都核对过？口径不同的数字没被直接比较？
- [ ] 反面证据检索过吗？主要结论都做过对抗性检验吗？
- [ ] 完整度低于 `partial` 的来源没单独支撑关键结论？

### 平衡与诚实

- [ ] 有没有明显遗漏的维度？（对照 `scoping.md` 的类型骨架扫一遍）
- [ ] 分歧是否如实呈现，包括与自己判断相反的证据？
- [ ] 事实 / 推断 / 推测分开写了？置信度标注了理由？
- [ ] 时效：标注了「截至某日期」？用的是最新可得信息？
- [ ] 假设和局限如实披露？「已采纳的假设」逐条复述进「方法与局限」？

### 数据资产

- [ ] brief 中每项数据需求已获得，或缺口及影响已披露？不可得/不适用理由成立？
- [ ] 数字、分类、事件等关键数据已进数据集，报告与记录一致？不能只关联一条记录就声称全部覆盖。
- [ ] 提取值与原始文件的页码/表/单元格或快照逐项一致？工具摘要没有被误标原文？
- [ ] 行粒度、口径、币种、期间、地域和字段字典足以支持复用？unknown 是否影响关键判断？
- [ ] 冲突值分别保留，选取、排除与转换理由可复核？多来源是否实际上同源？
- [ ] 派生数据的全部输入存在且口径可比？实际重跑自编计算或独立代入算式，对照结果并记录？
- [ ] 定性编码标准与歧义明确，没有把研究者推断写成原始披露？

### 研究包完整性

- [ ] 元数据齐全，没有孤立文件，无法存档的来源都写明了原因
- [ ] `raw/` 未被事后改动；更正只在 `notes/`、`data/`、`analysis/`
- [ ] README 统计由封包脚本生成，无法解析/未覆盖的材料均已处理，不手填通过状态
- [ ] 内部资料已标注；机密信息没写进公开检索查询

人工核验保存 `qa/review.json`，四项 checks 均写明实际核验位置/理由（模板 `../assets/review-template.json`）。完成后绑定 `--review-digest`，内容变更后复核。封包顺序见 `package-lifecycle.md`；`--write-manifest` 失败不得生成新的交付通过记录。

### 高风险领域

- [ ] 医疗 / 法律 / 金融：局限已注明，列出需向专业人士确认的问题

## 2. 红队审稿

有子代理可用时，派一个**全新上下文**的子代理当审稿人：

> 你是独立审稿人。只读这个研究包，不接受作者的任何说明。从 `report.md` 的关键结论出发，逐条追溯到 `raw/sources/` 里的快照原文，回答：
>
> 1. 这条结论的引用**确实支撑**它吗？撑不住的地方在哪？
> 2. 哪些表述说过头了（因果当相关、个例当普遍、样本外推）？
> 3. 哪条结论其实只有一条弱来源撑着？
> 4. 有没有结论在快照里找不到出处？
> 5. 反面证据是否被公平呈现？
> 6. 报告关键数据是否进入数据集，能否追到原始值？派生过程能复算吗？
>
> 输出：问题清单（结论 → 问题 → 证据位置），按严重度排序。不要客套。

审稿人只读研究包，不读对话历史——这样才不受作者叙述影响。审稿发现的问题要改完再交付。

## 3. 自评标准

交付前给研究包打一个**如实**的等级，只报实际达到的最高级：

| 级别 | 判据 |
|---|---|
| 可追溯 | 每条关键结论能从报告一路追到快照原文，自动检查零错误，人工核验已完成，v2 的 `--final` 通过 |
| 可复现 | 上一级 + 计算过程已实际复跑或独立代入验证（`analysis/` 方法 + data/ 输入与结果），检索记录完整；若未检索则披露原因 |
| 经对抗 | 上一级 + 主要结论做过反面检索、经过独立红队审稿 |
| 可决策 | 上一级 + 直接回答了核心问题、给出 so what、假设与局限足以支撑决策判断 |

达不到就如实报低一级，不越级声称。差在哪一级，就在「未解问题」里写明。
