## 1. 综合：从证据到结论

顺序固定：**先回答，再论证**。

1. **结论先行**：执行摘要直接回答核心问题，再展开论据。读者不该在第三节才找到答案。
2. **每条关键结论三段式**：
   - **结论**——一句话主张
   - **证据**——带引用的论据（数字、口径、时点、来源对照）
   - **so what**——对用户决策意味着什么
3. **只引用 `sources.md` 里已登记的来源**。写关键结论时回到快照原文核对，不依赖记忆——上下文被压缩后，记忆里的「原文」是最容易出错的环节。
4. 计算方法（增长率、换算、汇总）放进 `analysis/`，结果表放 `data/curated/`，保留 input_ids 与方法路径。关键数据用 `[数据:记录ID](data/…csv)` 关联，人工核对记录与报告一致，详细规则见 `data-package.md`。

## 2. 置信度与事实分层

| 分层 | 写法 | 例子 |
|---|---|---|
| 事实 | 有引用的可核对陈述 | 「2025 年出货量 120 万台（口径：厂商自报）[3]」 |
| 推断 | 明确标注「推断」，写清依据 | 「推断：按此口径，实际用户规模约为出货量的六成」 |
| 推测 | 明确标注「推测」，不得混入事实段 | 「推测：若补贴退坡，增速将下台阶」 |

每条关键结论标**置信度（高 / 中 / 低）**并给理由：

- **高**：一手来源或 ≥2 个独立可靠来源，口径清晰，无有力反证。
- **中**：证据可靠但单一、口径有局限、或存在未裁决的小分歧。
- **低**：间接证据、二手转述、样本小、反证未排除。

不夸大结论：证据只支撑「相关」就不要写成「因果」；样本只覆盖一类场景就不要外推成普遍规律。

## 3. 分歧怎么写

在「分歧与不确定性」里，对每处分歧交代四件事：

1. 谁持什么观点（带引用）
2. 为什么不同（口径 / 时间 / 方法 / 立场）
3. 你的判断是什么、依据是什么
4. 什么证据会改变这个判断

无法裁决的**并列呈现**，不硬凑一个「折中真相」。分歧本身是发现，往往指向口径问题或未公开信息。

## 4. 写作规则

- **正文不写过程叙述**。「我搜索了……」「我查阅了大量资料……」这类放进「方法与局限」和研究包；正文只留结论与证据。
- **同一来源全文只用一个编号**。一个来源支撑多条结论时复用同一编号，不在参考列表里重复列。
- **对比用表格**。三个以上对象、两个以上维度的比较，表格永远优于段落。
- **时效性事实标注日期**。「目前市场第二」必须写成「截至 2026-09，按 X 口径市场第二」。
- **不夸大结论**：见 §2。
- **术语前后一致**。同一概念全篇一个叫法；必须换说法时在首次出现处括注。
- 语言跟随用户；专有名词保留原文，必要时括注中文。

## 5. 七类报告结构

选定研究类型后套对应骨架，按实际发现增删小节。共同部分（执行摘要、分歧与不确定性、未解问题、方法与局限、参考来源）每类都要有。

### 行业 / 市场全景

1. 执行摘要（格局判断 + 3–5 条关键结论）
2. 范围与口径（研究的是什么市场、规模怎么算）
3. 格局：参与者分类与各自立足点（对比表）
4. 驱动因素与抑制因素
5. 产业链与价值分配
6. 趋势与可验证情景
7. 分歧与不确定性 → 启示与建议 → 未解问题 → 方法与局限 → 参考来源

### 对比选型

1. 执行摘要（选型结论 + 适用条件）
2. 选型场景与约束（要支撑什么动作、硬约束是什么）
3. 评估维度与权重（说明维度从哪来）
4. 对比矩阵（维度 × 候选，每格填证据与出处，不留空话）
5. 分场景结论：什么条件下选 A / B / C
6. 隐藏成本与退出风险
7. 证据不足的维度（需用户自测）
8. 分歧 → 建议 → 未解问题 → 方法与局限 → 参考来源

### 技术深潜

1. 执行摘要（机制判断 + 成熟度判断）
2. 机制：它怎么工作、关键假设
3. 有效性边界：什么时候行、什么时候不行
4. 代价：计算 / 经济 / 组织成本（带口径）
5. 与替代方案对比
6. 可复现性与失败案例
7. 前沿与未解决问题
8. 分歧 → 启示 → 未解问题 → 方法与局限 → 参考来源

### 公司 / 人物尽调

1. 执行摘要（可信度判断 + 主要风险）
2. 事实底稿：注册、股权、财务、法律与监管记录
3. 业务与现金流：靠什么赚钱、可持续性
4. 管理层公开言论 vs 实际成绩
5. 多方口径印证（客户 / 供应商 / 离职员工 / 竞对）
6. **风险信号清单**（每条：信号 → 来源 → 严重度 → 还需查什么）
7. 分歧 → 启示与建议 → 未解问题 → 方法与局限 → 参考来源

### 文献综述

1. 执行摘要（共识 / 争议 / 空白三句话）
2. 研问题与检索范围（数据库、关键词、时间窗）
3. 理论脉络与代表作
4. **共识**：被多个独立团队重复验证的结论
5. **争议**：分歧点与分歧来源
6. **研究空白**
7. 方法学问题（样本、测量、外推边界）
8. 分歧 → 启示 → 未解问题 → 方法与局限 → 参考来源

### 政策法规

1. 执行摘要（影响判断 + 时间点）
2. 条文原文要点（关键定义与适用范围，引原文）
3. 生效时间、过渡期、溯及力
4. 对目标对象的具体影响：义务 / 成本 / 机会
5. 执法口径与已知案例
6. 与既有法规的关系
7. **需向专业人士确认的问题清单**（律师 / 会计师 / 监管）
8. 分歧 → 建议 → 未解问题 → 方法与局限 → 参考来源

### 事实核查

1. **结论评级**（真 / 大致真 / 存疑 / 大致假 / 假 / 无法判定）+ 一句话依据
2. 主张的精确表述（可证伪版本）
3. **证据链**：最早出处 → 传播链改写 → 支持证据 → 反面证据
4. 数字口径核对
5. 什么证据会改变评级
6. 方法与局限 → 参考来源

## 6. 参考来源条目格式

**格式固定，勿改**——`check_package.py` 依赖行尾的「来源 ID `X` 存档 [路径](路径)」解析。

```markdown
- [1] 作者/机构. 标题原文. 2025-03-15. https://example.com/a. 访问 2026-09-26. 来源 ID `M001` 存档 [raw/sources/M001-example.md](raw/sources/M001-example.md)
```

规则：

- 编号从小到大连续；正文引用号必须在本列表有对应条目
- 本地路径用**相对路径**的 Markdown 链接，点击即可打开
- 发布日期未知写 `unknown`
- 完整骨架见 `../assets/report-template.md`
