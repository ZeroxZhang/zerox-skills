# 场景 1 · 简单事实题

**推演视角**：刚加载 `zerox-deep-research` 的新会话，只看到 description 与 SKILL.md，没读过本文档。

## 被测请求

> 苹果现任 CEO 是谁？

## 触发判定

**不应触发。** description 末句写明「不用于单一事实查询或简单问答」。单一事实查询是工具调用级别的任务，不是研究任务；套 description 只会让流程拖慢回答。

skill-creator 的触发机制说明也支持这一点：简单一步查询本来就不倾向触发 skill——这里的边界句是双保险（防「深度研究」「查一下」等词误拉起全流程）。

## 若用户显式点名要用本 skill

> 用 zerox-deep-research 查一下苹果现任 CEO 是谁

此时**应触发**（用户明确指令优先），但必须走轻路径：

| 期望行为 | skill 依据 |
|---|---|
| 定级为 **L1**，不走完整流程 | SKILL.md 阶段 0：「L1 快速：单一事实或定义。不走完整流程，3–10 次工具调用」 |
| 简短回答 + 来源 | 同上 |
| **不建研究包** | 同上：「默认不建研究包」 |
| 不问澄清问题 | scoping.md §4：澄清只用于「会实质改变研究方向」的问题；事实题的方向不存在 |
| 不写 brief.md、不进计划确认闸门 | 阶段 1、2 明确标注针对 L2/L3 |

### 例外分支

用户若说「查一下苹果现任 CEO，把资料都留档」→ 走 L1 简化包：只含 `raw/` 与 `answer.md`（阶段 0 明文）。此时仍**不应**产出 report.md / brief.md / plan.md 全套。

## 推演结果

**通过。** SKILL.md 阶段 0 的 L1 条款与 description 边界句共同覆盖：

1. 误触发场景有边界句挡住；
2. 显式点名时有轻路径，不会把 3 分钟的事做成 30 分钟。

## 残留风险

「苹果现任 CEO」这类问题如果查不到权威口径（比如换任当天），agent 可能倾向展开研究。阶段 0 的 3–10 次工具调用预算是硬约束，能挡住跑飞。
