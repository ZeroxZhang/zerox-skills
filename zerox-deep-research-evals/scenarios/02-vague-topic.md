# 场景 2 · 模糊的大题

**推演视角**：刚加载 skill 的新会话。

## 被测请求

> 帮我研究一下 AI 眼镜

## 触发判定

**应触发。** 「研究一下」+ 开放性主题落在 description 的「深度研究 / 系统调研」触发面内。这类请求是本 skill 的核心用途，不是误触发。

## 期望行为

| # | 期望 | skill 依据 |
|---|---|---|
| 1 | **先定级**：宽泛多维、用途不明 → L3（至少 L2 上限） | 阶段 0：「宽泛、多维或高风险决策 → L3」 |
| 2 | **先摸底再提问**：3–5 次宽泛检索弄清全景、关键术语、权威信源，才能问出好问题 | 阶段 1.4 |
| 3 | **摸底也入包**：摸底检索记检索日志，读过的相关来源照样存档 | 阶段 1.4 明文 |
| 4 | **澄清**：只问实质改变方向的问题，1–3 个、最多 5 个，**每个附默认选项**，让用户一句话能回 | 阶段 1.5 + scoping.md §4 |
| 5 | **产出简报并等待确认**：brief.md 写完，展示精简版（核心问题 / 子问题 / 假设 / 交付物 / 预算）等确认 | 阶段 2 计划确认闸门 |
| 6 | 确认前**不开始大规模检索** | 阶段 2：「确认或修改后更新 brief.md……再开始大规模检索」 |

## 推演：澄清问题会问什么

scoping.md §4 的高价值维度，对着「AI 眼镜」这个模糊题，agent 应挑出方向性最强的 1–3 个，并带默认值：

1. **用途与决策**——是要投研、产品立项、还是写内容？
   默认：支撑一次内部方向讨论，不做最终决策。
2. **范围（地域/细分）**——整机生态、光学显示、还是应用层？
   默认：中国大陆为主、海外作对照；聚焦消费级整机与上游供应链。
3. **交付形式与篇幅**
   默认：Markdown 报告 + 完整研究包，正文 3000–6000 字。

问 5 个以上就违反「一次问完，通常 1–3 个，最多 5 个」；不带默认选项就违反「让用户一句话就能回复」。

## 推演结果

**通过（静态推演）**。流程顺序正确：定级 → 摸底 → 澄清 → brief → 闸门等待。

## 与真实运行的差距

静态推演无法验证两件事，必须实跑：

1. agent 会不会**先摸底再问**——不摸底就提问，问题会问得空泛（「你想了解哪方面？」这种开放问题是失败模式）；
2. 澄清问题是否真的带默认值、真的只问 1–3 个。
