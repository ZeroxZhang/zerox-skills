# 业务评价、风险与可选评分

公司研究 `company_research` 用分项理解、关键未知和置信度表达结果，不发布综合分。六类商业专项也默认不评分；只有确实需要统一比较且量尺有解释力时启用 `scoring_enabled=true`。业务适配、具体风险和证据充分程度始终分别判断，分数不能抵销法定禁止或用户明确的否决条件。

## 先确定本项目的判断条件

先从研究问题与关键声明确定哪些维度不能缺证，再考虑权重。`data-contract.json` 中的权重、关键维度和评价主题只是候选配置；启用评分后须用 `scoring_override` 明确 `reason`、完整 `weights` 和 `critical_dimensions`。理由说明与核心问题的对应关系，包括采用默认值的依据；不能只为达到覆盖率而删去关键维度。

| 目的 | 确定不可缺条件时优先考虑 |
| --- | --- |
| 投资 | 需求与单位经济、可持续盈利和现金、投资权利；增长驱动价值时增长不可缺，评价具体价格时交易价值与下行条件不可缺 |
| 并购 | 独立经营、净债务与营运资本、权属与交割；协同和整合是交易依据时须核验各自前提 |
| 合作 | 资源匹配、交付能力、权利/数据使用与双方责任；不能以潜力替代已具备的履约条件 |
| 授信 | 实际付款主体、可用现金、到期义务与增信可执行性；偿还来源不能由集团名气替代 |
| 供应商准入 | 质量、交付连续性、替代供给与预付款风险；按拟采购品类和规模判断 |
| 竞品研究 | 同场景客户选择、产品效果、定价与渠道、资源和约束；不转成交易或授信审批 |

## 共用量尺

契约 `scoring.scale` 定义同一量尺，各目的的 `criteria` 指定评价主题。项目须把主题转成可观察条件、可比范围与证据，在 `scorecard.anchor` 记录具体判断，不能仅复制通用句子。

| 分数 | 解释 |
| --- | --- |
| 1 | 已证实不满足本次目的的关键条件 |
| 2 | 部分满足，但存在尚未验证解决的重大短板 |
| 3 | 满足已定义的基本条件，仍有明确限制 |
| 4 | 持续满足条件，跨期或独立材料支持其稳定性 |
| 5 | 同口径优于有依据的可比基准，优势持续性及关键反证已检验 |

未知不等于1分或3分。所有启用维度保留行，缺证填空并说明原因；不适用需理由。非空分数须为1–5，具有证据、具体锚点和高/中置信度。低/未知置信度不计入充分覆盖。同一风险不重复扣分；若影响多个目标，解释不同传导路径。

## 发布条件与计算

设适用维度集合为 A，有充分证据可评分的集合为 K：

- 加权证据覆盖率 = K 的原始权重之和 / A 的原始权重之和。
- 已覆盖维度分数 = K 的分数与原始权重乘积之和 / K 的原始权重之和。

只有项目判断条件已确认、覆盖率达到 `scoring_threshold`、全部关键维度有充分证据、没有 critical 开放缺口或足以改变判断的重大未解冲突时，第二项才可发布为综合分。默认80%是可配置管理阈值，不是统计置信度或行业标准；覆盖80%也不能替代关键问题验证。否则仅保留分项或局部分数，明确不足。

A为空时不适用；A非空而K为空时覆盖率为0、分数为null。权重必须有限且非负、适用权重总和大于0；关键维度必须存在，不能通过标不适用使其消失。`scoring.py` 验证算术与条件，分析者仍须确认所选条件和证据实质上成立。

`research_gate` 单独说明研报资料覆盖；评分不修改它，也不代替研究范围完成审核。`published_score` 仅记录实际发布且已通过检查的总分。旧项目未启用评分时不自动恢复历史总分；需先复核适用条件再明确启用。

## 风险与行动

红旗先核实身份、当前状态、适用范围和替代解释；未经核实不自动否决。关键事实缺失可使判断暂缓，不等于风险已发生。行动条件说明依据、完成标准、责任角色和残余风险；投资评价同时考虑价格、资金需求、权利和回报。更新触发可列出，但外部联系、交易和自动监控仍须用户授权。
