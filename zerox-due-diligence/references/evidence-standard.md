# 证据标准与数据契约

仅使用以下七类声明标签，定义集中于 `data-contract.json` 和 `evidence-standard.md`，其他文件引用同一规范：

| 标签 | 含义 |
|---|---|
| 【事实】 | 有资料支持的事件或状态，必须说明主体与范围 |
| 【数据】 | 可量化的实际数据，含口径、期间、单位与来源 |
| 【推断】 | 本项目基于证据和明确假设作出的推理或估算 |
| 【判断】 | 本项目基于事实和标准作出的评价或建议 |
| 【第三方观点】 | 机构/个人的评价、预测、评级、目标价或管理层指引 |
| 【待核实】 | 存在线索但支持不足、身份未确认或有未解决冲突 |
| 【缺口】 | 必需信息缺失或尚未取得 |

针对关键结论、表格行和风险项标注，避免给标题、纯说明句、模板提示机械加标签。

预测数字仍归【第三方观点】或【推断】，不能仅因包含数字就归为实际【数据】。派生的实际财务比率可归【数据】，但必须指向输入证据与公式。

## 通用研究与核验规则

各模块沿用本节，不重复建立一套证据规则。检查结果应能定位到证据、未解决问题及下一步：

- 主体、合并/单体/分部范围、期间、币种/单位和实际/预测属性先于计算或比较；发布日期、资料期间、访问日分开。缺失保留原因与缺口，不补0或行业均值；不适用须有依据。
- 原件可在直接覆盖范围内支持事实；重大解释和判断主动检验独立证据与合理替代解释。共同原件按 `origin_group` 去重，来源等级不等于置信度，官方发布不等于全部内容经核验。
- 冲突先对齐主体、期间、口径与版本；仍有差异时记录双方依据、采信理由和对结论的影响。不能用平均、删去反证或调低重大性来消除冲突。
- 风险线索先核实事实、替代解释与传导路径，再说明承担主体、影响时间、缓释和关闭条件。缺资料或无检索结果均不直接证明有风险或无风险。
- 分析应能还原“解释为何成立、什么证据会改变它”。当前解释写入声明表 `statement`，成立前提与替代解释复用 `assumptions`，区分检验与反证复用 `counterevidence`，未解决事项与改变判断条件复用 `unresolved`；证据关系与资料缺口仍用现有表，不新增假设台账。
- 假设经直接反证推翻时保留原声明，标为 `verification=refuted`，在 `counterevidence` 写驳回依据并关联 `contradicts` 证据；置信度表示对驳回判断的把握。只有高/中置信且无未解决事项才算已处置，修正结论另建声明。`unsupported` 仅表示支持不足，不能冒充已推翻。

抽样合同、订单、客户或访谈时，记录总体/观察期间、覆盖范围、谁提供或挑选样本、选样方法及不可得部分。按问题检查失败、流失、退货、逾期或其他异常样本，避免只用管理层挑选的成功案例；便利样本仅支持其观察范围，外推总体需说明额外依据。访谈对象数量、证据条数或样本占比本身不是结论置信度。

## 来源分类与置信度

保留 S/A/B/C/D 五级来源属性以便排序：

- S：官方登记、监管/司法文件、法定披露、经核验的审计文件等，限于其真实覆盖范围。
- A：有透明方法与可追溯原始材料的高质量调查、统计或独立核验资料。
- B：券商研究、专业研究和商业数据库等，需进一步区分原始数据、转载、估算与观点。
- C：企业宣传、管理层自述、一般报道、访谈等需核验材料。
- D：匿名、无法追溯、身份不明或可靠性明显不足的线索。

评级是默认起点，可依据具体材料调整并说明原因；获取渠道不决定来源类型。签字合同只能在确认真实性后支持合同内容与当事方表示，不自动证明履行、付款或盈利。

置信度按声明单独评为高/中/低/无法判断，综合：

1. 是否直接支持该声明。
2. 是否原始、真实且取得了足够正文。
3. 主体、期间、口径、版本是否匹配。
4. 是否有独立印证和重要反证。
5. 利益关系、方法局限及尚未解决的冲突。

不使用“最高来源等级 × 来源数量”作为机械置信度公式。多名访谈对象意见相同，也不能自动改变原始证据类型。

## 台账结构

使用“来源—证据片段—声明—关联”结构，避免一条记录同时承担文档、观点和结论的多种身份。

- 来源 `S-0001`：一份具体版本的文件或页面。
- 证据 `E-0001`：该来源中能够支持或反驳某事的定位片段。
- 声明 `C-0001`：一个需要核验或在报告中提出的具体陈述。
- 研报 `R-0001`：与来源关联的研报目录记录。
- 其他对象可使用 `ENT-`、`G-`、`K-`、`F-` 等唯一前缀；在数据契约中统一。

正文引用格式为 `[E-0001]`；附录映射至真实 URL 或文件与页码。一个声明可关联多个证据，一个证据也可支持多个声明；通过关联表记录。

| 文件 | 核心字段 |
|---|---|
| entity-map.csv | entity_id、法定名、注册号/可核验标识、别名、地域、证券代码/交易所/类别、实体类型、身份/上市状态、证据 |
| entity-relations.csv | relation_id、parent_id、child_id、关系类型、比例、控制依据、有效期间、当前/历史/拟议状态、核验状态、证据 |
| search-log.csv | 检索 ID、时间、工具/渠道、查询词、对象、期间、目的、结果/失败状态、候选来源、覆盖限制 |
| source-register.csv | source_id、标题、来源类型、机构/作者、原始发布/修订/访问日期、URL/本地定位、来源等级、原始来源组、获取状态、真实性核验、授权范围 |
| evidence-ledger.csv | evidence_id、source_id、实体/分部、模块、页码/表/段落、简短摘录或释义、数据期间、币种/单位/口径、实际/预测属性、访问局限 |
| claim-register.csv | claim_id、陈述、标签、实体、模块、重大性、核验状态、置信度、推理/假设、反证、未解决问题 |
| claim-evidence.csv | claim_id、evidence_id、关系（支持/反驳/背景）、适用范围、限制与解释 |
| research-register.csv | research_id、source_id、机构/作者/标题/类别、覆盖实体/证券、报告日期/版本、数据截止/预测期、最新性角色、事件覆盖、获取状态、阅读状态、目标相关章节、利益披露、关键观点、局限 |
| research-coverage.csv | 覆盖项 ID、目标实体、所需类别、是否必需及理由、检索状态、最新发现/全文/已读报告 ID、事件覆盖、门槛状态、缺口 ID；未发现报告时相关报告 ID 合法留空 |
| conflict-register.csv | 冲突 ID、相关声明/证据、双方值/口径、原因分析、处理状态、采信理由、决策影响 |
| gap-register.csv | gap_id、所需信息、模块/实体、原因、重大性、受影响结论、获取方式、优先级、责任角色、状态 |
| risk-register.csv | risk_id、风险内容、承担主体、状态、证据、影响、可能性、时间范围、替代解释、缓释、残余风险、关闭条件 |
| scorecard.csv | 目的、维度、权重、适用性、分数或缺失、评分锚点、证据、置信度、覆盖状态 |

`research-register.csv` 必须能分别标记“最新发现”“最新取得全文”“最新已读”，不能用一个布尔值掩盖差异。

在 `research-coverage.csv` 为每个触发研报流程的目标与相关上市主体预先建立全部必读类别的覆盖项，避免“没有报告记录”被检查器误判为“没有问题”。具体报告可覆盖多个类别，但须逐类别说明相关性，不能重复计算独立来源。实体与控制关系如存在多条边，应使用可表达多关系的记录结构，不能用单一母实体字段丢失共同控制或多层关系。

各 CSV 提供真实表头；枚举、字段类型、必填/条件必填、日期、空值、多值编码和跨表引用规则写入数据契约。脚本从同一契约加载规则，禁止各自维护不同标签或列名。

## 缺失、冲突与引用

- 缺失原因区分：未披露、未找到、访问受限、不可读、未执行、口径不适用。
- 不适用必须有理由；不能为了提高覆盖率把未知改成不适用。
- 原始来源无法取得时，保留二手引用关系，不虚称已直接访问原始来源。
- 实际摘录遵守授权与适用引用限制，以必要的短摘录和定位为主；“固定 200 字”不能作为通用版权许可。
- 个人访谈记录身份类别、日期、知情范围、利益关系与匿名约定，不输出不必要的个人信息。
- 缺少具体原件时不编页码；网页用段落/标题定位，PDF 区分印刷页与文件页。

## 实现口径

机器值和中文含义分别记录；枚举与条件必填在 [data-contract.json](../schemas/data-contract.json) 中维护，脚本直接加载，不能另起同义标签。

- `entity-map` 只记实体；多条控制/关联边放 `entity-relations`。实体 `ENT-`、关系 `REL-`、检索 `Q-`、来源 `S-`、证据 `E-`、声明 `C-`、关联 `CE-`、研报 `R-`、覆盖 `RC-`、冲突 `F-`、缺口 `G-`、风险 `K-`、评分 `SC-`；至少四位数字。
- CSV 严格匹配模板列；UTF-8，空单元格是 null，数值 0 保留。多值为 JSON 数组，例如 `["E-0001","E-0002"]`；CSV 用双引号转义，不用分号拼接。日期 `YYYY-MM-DD`，时间含时区。
- `scope`：consolidated 合并、standalone 单体、segment 分部、brand 品牌、not_applicable 非定量；定量不得无范围。非货币数量 `currency` 可写 N/A，单位不能省略。
- `attribute`：actual 实际、forecast 第三方预测、estimate 本项目估算、opinion 观点、not_applicable 非数据。forecast/estimate 禁止转为实际【数据】。公式所得实际比率应关联输入证据。
- `time_scope=retrospective` 是明确隔离的事后补充，不可关联为历史时点结论的支持证据。修订日期晚于基准日亦不得冒充当时可得。
- 原始发布日期未知时 `published_date=null`，在 `grade_reason` 说明日期缺失及其时点限制，不用访问日补齐。发布与修订日期均未知且在基准日之后才取得的材料必须为 retrospective；截止日前已取得只证明当时可得，不证明发布日期或最新性。研报目录仍须有与来源相符的真实报告日期，无日期资料不能参与“最新研报”判定。
- `identity_status`：pending 待确认、resolved 已消歧、ambiguous 多候选；疑似同名分别建实体，不能混并。
- 来源 `origin_group` 表示共同原件，`upstream_source_id` 保留已发现的二手引用链。获取状态和等级不决定置信度。
- 缺口原因映射：not_disclosed 未披露、not_found 未找到、access_restricted 访问受限、unreadable 不可读、not_executed 未执行、not_applicable 口径不适用。
- 正文证据指针不能凭空创建；新来源/实体/证据有循环引用时用 `add --input` 的批量对象提交。读取元数据只能建来源或研报候选，不能创建其正文证据。
- `latest_discovered_for/latest_fulltext_for/latest_read_for` 为覆盖ID数组，与覆盖表三个指针互相对应；不要手工使用一个“最新”布尔值。
- `completed_actions` 是动作、状态、证据ID、结果定位的对象数组；例如访谈 planned 只表示提纲已准备，不能计作已访谈。
