## 1. 章节骨架

```
标题
执行摘要（200–400 字）
引言（SCQA，只铺垫不论证）
正文
  第一章 = 支撑点一（章首句即本章结论）
    1.1 子论点 → 证据（数据 / 案例 / 原话）
    1.2 子论点 → 证据
  第二章 = 支撑点二
  …
结论与建议
风险、前提与待决问题
附录（详细数据、案例、方法说明、术语对照、来源清单）
```

章的顺序就是阶段 3 结构树的顺序，不在写作阶段重新编排。写作中若发现某章撑不起来，**回到阶段 3 改主线**，不要在正文里注水。

## 2. 段落规则

| 规则 | 说明 |
|---|---|
| **一段一个意思** | 一段里出现两个论点，拆开。读者记不住并列的两个结论 |
| **首句即观点句** | 每段第一句是结论，后面才是依据。这一句稍作改写就是 PPT 的行动标题，写不好说明这一段没想清 |
| **具体胜于抽象** | 能用数字、案例、原话的地方，不用形容词。「增长显著」→「同比 +12.4%」；「反响良好」→「5 位受访者中有 4 位主动提及」 |
| **主语明确** | 谁做什么。「经研究决定」→「董事会决定」。被动句只在施动者确实无关时用 |
| **不用序数词当结构** | 「首先 / 其次 / 最后」是拼凑的标志。用内容关系连接：因果、递进、对照 |
| **段长 3–6 句** | 超过 6 句考虑拆分；1–2 句的段落连续出现说明该合并 |
| **直接引用要标记** | 原话加引号并注明说话人角色与来源（`S04-访谈3`） |

**反向写作法**（推荐）：先把每个子论点的首句写出来排成一列，检查这列句子是否构成一条完整的论证链——能，就逐句扩写成段；不能，说明结构树有问题。

## 3. 标注规范

| 用途 | 格式 | 例 |
|---|---|---|
| 卡片与来源 | 紧跟被支撑的句子之后 | 上海现制茶饮市场同比仅增长 8.2%〔C012｜S03-§2.1〕 |
| 多张卡片 | 用 `、` 分隔 | 〔C018、C031｜S01-表2〕 |
| 推断 | 显式写出「推断」二字，列出依据卡 | 我们推断租金每涨 10%，回本周期延长约 5 个月（推断｜依据 C018、C031） |
| 证据缺口 | 方括号占位，写清缺什么 | 【待补充：上海核心商圈 2026 年租金的第三方口径数据】 |
| 外部补充 | 单独标注，写出来源 | 【外部补充：据国家统计局 2026 年 6 月数据，…（来源：stats.gov.cn/…）】 |
| 派生数据 | 与材料卡片同格式；来源写输入卡 | 〔C175｜派生自 C005、C012〕 |

三条纪律：

1. **卡片 ID 必须真实存在**。脚本会检查悬空引用，引用不存在的卡片是错误。
2. **推断不得伪装成事实**。凡是自己算出来、推出来的，都要带「推断」二字，并列出依据卡片。建议值、目标值、测算值同理——它们本来就允许是材料里没有的数（「建议先开 8 家」），但必须带上「建议 / 目标 / 测算」这类标记并说明依据从哪来。**没有标记又查不到出处的数字，脚本按编造处理**；这是刻意的：标记本身就是作者对自己说的话负责的方式。
3. **缺口不得编造填充**。宁可留【待补充】，也不能写一个看起来合理但没来源的数字。
4. **日期与序号不需要单独标注来源**。「2026 年 3 月的董事会」「第六章」是叙事脚手架，脚本不再要求它们带引注。**不要为了让脚本安静而把内容改写成「上一次会议」「对应章节」这类回避写法**——那会丢掉读者需要的信息。
   但要注意豁免的边界：**带引用的句子里，日期和其他数字一样要在所引卡片的「内容」栏里找得到**。所以写「3 月董事会」并引了某张卡时，那张卡的内容栏里就得有「3 月」这两个字（卡片写 `2026 年 3 月 6 日` 而不是 `2026-03-06`）。改回自然日期写法时顺手核一下，比在正文里绕开更省事。
   日期一旦进了论据（「2027-06-30 前不得超过 15 家」），它就是数据，照常标注来源。
5. **自己算出来的数走派生卡片**（见 `info-extraction.md` §10），不要在正文里直接给一个算式而不留卡片。脚本核对的是数字能否回溯到卡片，推算过程留在派生卡片的「内容」栏里才可复核。

## 4. 执行摘要

200–400 字，**可独立阅读**——只读它的人应该能拿到结论与主要理由。

结构：中心论点（1 句）→ 2–4 条主要理由（各 1 句，带关键数字）→ 结论或请求（1 句）。

- 不写「本文分为四部分」「首先介绍背景」这类导航句。
- 不出现正文里没有的数字。
- 不出现【待补充】：摘要里放不下的证据，说明「主要证据见第 X 章」。
- 写成后再检查一次：把摘要单独发给一个不了解项目的人，他能说出你要他做什么吗？

## 5. 结论与建议章

| 要素 | 要求 |
|---|---|
| 行动 | 具体到可执行的动作，不是方向。「加强品牌建设」不合格 |
| 优先级 | 排序依据写出来（影响 × 紧迫性 / 依赖关系） |
| 负责人与时间 | 材料支持时写明；材料未提供就写【待补充：责任人】，不要编 |
| 与正文的对应 | 每条建议都能指向正文的某一章 |

建议章**不引入正文没有的新证据**。出现了，说明该证据本该在正文里。

## 6. 风险、前提与待决问题

分三块，不要混：

- **风险**：可能发生且会造成损失的事，写触发条件与影响，能写缓解措施就写。
- **前提**：整份结论成立所依赖的假设。前提被推翻，结论就要重估——这一块是给读者用来攻击你的，主动交出去比被问出来好。
- **待决问题**：现在没有答案、需要用户或第三方拍板的事，写清「谁能答」「需什么信息」。

少数派证据、与主流结论冲突的材料，在这里有一次露脸机会；没有被主线采用但影响判断的，也放这里。

## 7. 附录

放详细数据表、案例全文、方法说明（怎么算的）、术语与口径对照表、来源清单。

附录的作用是让主线保持干净的同时不丢信息。**被移出主线但仍有价值的卡片，应该有相当一部分落在这里**，而不是消失。

**来源清单只列本报告实际引用过的来源**，不列全部材料——「这批材料一共收到哪些」是 `01_materials_index.md` 的职责。两者分开，附录 E 才不会把与议题无关的材料（C 级、未引用）拉进交付物。

## 8. 清洁版

`04_manuscript_clean.md`：删除全部〔C…｜S…〕追溯标注，供对外阅读。

- **保留**推断标注与【待补充】占位——它们不是追溯标注，是对读者的诚实交代。
- 数字、单位、限定条件、结论与母版**逐字一致**，不得因为「读起来更顺」而改写。
- 生成方式是机械删除标注，不是重写。生成后跑一次脚本一致性检查。
- 若用户要求连推断标注与缺口占位也去掉，另存对外版，并在审计报告登记移除了哪些提示。

## 9. 删词表

写完通读一遍，见一个删一个：

> 赋能、抓手、闭环、生态、深度融合、全面提升、高度重视、多措并举、持续发力、打造标杆、实现突破、提质增效、高质量发展、与时俱进、全力以赴、切实有效、在一定程度上、某种意义上、众所周知、毋庸置疑、不言而喻、综上所述、值得注意的是、需要指出的是

以及所有**没有数字支撑的程度副词**：显著、大幅、明显、较大、较快、比较、相对、有所、进一步。

以及**没有主语的判断句**：「业内普遍认为」「据了解」「相关数据显示」——换不成具体主语的，删掉。

**检验方法**：随便挑三段，把形容词和副词全划掉。剩下的话还能读懂、还成立，说明写的是内容；读不懂了，说明原来那些词就是内容，等于没写。
