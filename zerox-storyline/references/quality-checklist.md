## 1. 各阶段自检

**阶段 0**：七项信息齐（受众 / 目的 / 场景 / 语言风格 / 保密 / 外部知识 / 验收标准）→ 未确认的标了假设 → 提问 ≤5 个且每个有默认选项 → 页数或时长上限已定或标为未定。

**阶段 1**：每份材料有处理状态，**没有一份停在「未处理」** → 重复与多版本已裁定准据版本 → 长文档末段已读 → 低相关材料也做了略读级提取 → 分批的材料有进度表。

**阶段 2**：卡片字段齐全（A/B 级必须有「含义」）→ 卡片 ID 无重复无跳号 → 内容栏保留了单位与口径 → 原话加了引号 → 冲突建了清单 → 术语口径建了对照表 → 主题聚类有 A 级清单 → 少数派证据未低于 B 级。

**阶段 3**：候选主线 2–3 个且真正有差异 → 每个候选过了电梯测试 → 每个支撑点挂了卡片 ID 与证据强度 → 每个候选写了「放不进去的信息及安置方式」→ 压力测试三类质疑各有回应或缺口 → 确认点已过或已注明自动采用 → 结构树完整（中心论点 → 支撑点 → 子论点 → 卡片）。

**阶段 4**：每章首句是结论 → 每段首句是观点句 → 带引用的句子引用可解析 → 推断都标了「推断」→ 缺口写成【待补充】而不是编造 → 执行摘要 200–400 字且可独立阅读 → 建议章有优先级 → 风险 / 前提 / 待决问题分块 → 清洁版已生成且与母版数字一致 → 删词表过了一遍。

**阶段 5**：deck 类型已定 → 页数在预算内（或超出的已按顺序处置）→ 每页一个核心信息 → 标题是结论不是话题 → 只读标题能讲完故事 → 每页正文支撑标题 → 数据页写清图表类型 / 字段数值 / 高亮重点 → 每页有讲者备注与过渡语 → 备用页 ≥3 → 结尾是建议或请求决策 → 页面无卡片库之外的信息。

**阶段 6**：脚本跑通且零错误 → **覆盖审计按实际产出回查**（不采信阶段 3 的去向登记；脚本报的「只在故事线里挂了名」就是「排了没用上」）→ 逐条列出未使用的 A/B 卡 → 数字回查完成 → 一致性检查完成 → 冲突与缺口清单完整 → 未修正项写明原因。

## 2. 审计四查怎么查

### 覆盖审计

1. 跑 `python scripts/check_content.py <任务目录> --json`，拿到「未被引用的 A/B 级卡片」清单。
2. 对清单里每一张卡，人工判定去向并登记：正文某章 / 某页 / 讲者备注 / 备用页 / 附录 / 待定池 / 确认不用。
3. **A 级卡片不允许「确认不用」**——真用不上的，要么说明它其实该降级（并写清依据），要么说明主线有缺陷。
4. B 级进待定池要写明原因（过时、口径不可比、与主线无关）。
5. 输出格式：`卡片ID ｜ 等级 ｜ 去向 ｜ 说明`。

### 保真回查

按 §3 的步骤做，重点是**限定条件与因果强度**，这两样最容易在改写时蒸发。

### 结构检查

| 检查 | 方法 |
|---|---|
| 结论先行 | 只看全文首段、各章首句、各页标题——是否都是结论 |
| 以上统下 | 抽一个支撑点，读完它下面全部内容，是否超出支撑点那句话的信息量 |
| 归类分组 | 同一章的条目是否同一类别；能不能用一个词概括 |
| 逻辑递进 | 章内顺序是否有依据；把顺序打乱后是否明显变差（不明显 → 顺序是随意的） |
| MECE | 支撑点之间是否重叠（两个都在讲风险）；是否漏了明显的一类 |
| SCQA 有效性 | C 是否具体有证据；Q 是否由 C 自然导出且唯一；A 是否正面回答了 Q |
| 横向逻辑 | 按顺序只读行动标题（脚本 `--titles` 可直接输出） |
| 纵向逻辑 | 每页正文是否支撑该页标题 |
| 页数与时长 | 页数 ÷ 时长 是否落在 §3 的节奏区间内 |

### 一致性检查

1. 内容稿 ↔ 清洁版：数字、单位、限定条件逐项比对（脚本可查数字集合差异）。
2. 内容稿 ↔ PPT：术语一致（同一概念同一个词，对照表为准）、数字一致、结论一致。
3. PPT 内部：同一指标在不同页是否用了同一口径。

## 3. 数字回查操作步骤

1. 从内容稿中抽出**所有含数字的句子**，逐句标注来源状态：有引用标注 / 无引用标注。
2. **无引用标注的数字**：补卡片来源；或加「推断 / 建议 / 目标」标记并写明依据；或删除。没有第四选项。**日期与序号除外**（「2026 年 3 月」「第六章」是叙事脚手架，脚本已免检），自己算出来的数则建派生卡片。
3. **有引用标注的数字**：回到所引卡片的「内容」栏逐项核对五项——**数值、单位、时间、统计口径、限定条件**。任一项不同即为失真。
4. 核对**因果强度**：卡片写「相关」「可能」「在 X 条件下」，稿件是否被写成了「导致」「必然」「普遍」。
5. 核对**范围词**：卡片写「试点门店」，稿件是否被写成「全部门店」；卡片写「5 位受访者中 4 位」，是否被写成「受访者普遍认为」。
6. 反向查：把 A 级卡片里的关键数字列出来，检查是否进了正文；该进没进的写进审计报告并说明原因（很可能被漏掉了）。
7. 对 PPT 重复 1–5 步。

## 4. 反模式判定表

| # | 反模式 | 判定方法（做到即通过） |
|---|---|---|
| 1 | 形式化 SCQA | C 段里能找到至少一个具体数字或时点；把 C 读出来，能自然问出 Q；A 是断言且正面回答 Q |
| 2 | 话题式标题 | 行动标题列表里没有名词短语（「市场分析」）；每条标题含判断或数字 |
| 3 | 平均化摘要 | 正文中每一个「提升 / 下降 / 增长 / 改善」都能在后面 20 字内找到数字 |
| 4 | 丢掉反面证据或限定条件 | 卡片库里的冲突条目在稿件中能找到对应处理；抽查 5 个带限定条件的卡片，限定条件在稿件中保留 |
| 5 | 一页多结论 | 每页标题不含「与 / 及 / 同时」连接的并列结论；正文条目都支撑标题 |
| 6 | 出现卡片库外的数字或事实 | 脚本零「库外数字」错误；人工抽查 PPT 中 5 个数字能回溯到卡片 |
| 7 | 只处理前几份材料或长文档前部 | 材料索引里每份材料的处理状态不是「未处理」，长文档写明了读到哪一行；长文档的卡片来源定位里存在 `p` 大于总页数 60% 的引用 |
| 8 | 与主题无关的材料被塞进交付物 | 交付物（04/05/06）里搜不到无关材料的任何专有词；脚本的覆盖审计里它也确实是 C 级且只在卡片库与审计报告登记 |
| 9 | 去向表写了、正文里没有 | 脚本零「只在故事线里挂了名」；抽查 5 张卡片的登记去向，卡片 ID 确实出现在所指的位置 |

## 5. 脚本用法与能力边界

```bash
python3 scripts/check_content.py <任务目录>            # 人类可读检查
python3 scripts/check_content.py <任务目录> --json      # 机器可读，供审计报告引用
python3 scripts/check_content.py <任务目录> --titles    # 只输出行动标题序列（横向逻辑检查用）
python3 scripts/check_content.py <任务目录> --no-numbers  # 跳过较慢的数字回查
```

脚本检查：文件齐备性、卡片结构完整性、引用可解析（悬空引用）、A/B 级覆盖率、A 级占比校准、库外数字、清洁版与母版数字一致性、行动标题序列。

**「已安置」只认交付物**：只有卡片 ID 出现在 `04_manuscript.md`、`05_storyboard.md`、`06_slides.md` 里才算落地。只在 `03_storyline.md` 里挂了名 → 「排了但没用上」（A 级报错）；只出现在 `07_audit_report.md` 的登记表里 → 「只登记了没安置」（A 级报错，B 级警告）。这两类正是「静默丢弃」的实际发生方式，别看漏。

**错误与警告的分界**：带「推断 / 建议 / 目标 / 测算 / 上限 / 至少」这类标记的句子里的库外数字只报警告（它是作者的判断，不是材料事实）；没有这类标记又查不到出处的数字报错误（按编造处理）。

**日期豁免只作用于「未标注来源」这一项检查**，不作用于数字核对：带引用标注的句子里，日期和其他数字一样要能在所引卡片的「内容」栏里找到。两条合起来的正确读法是——**日期不必单独标注来源，但一旦出现在带引用的句子里，它就得在卡片里**。所以把「上一次会议」改回「3 月董事会」时，要同步把这个日期写进所引卡片的「内容」栏（例：卡片写「2026 年 3 月 6 日」而不是「2026-03-06」，否则「3 月」匹配不上）。

数字比对容忍四舍五入与万 / 亿换算，因此「库外数字」为 0 不等于口径正确——仍需人工核对口径。

**A 级占比校准**：卡片数 ≥20 且 A 级占比 ≥35% 时脚本给出提醒。这条不是格式错误，是判据可能用错了——A 级问的是「抽掉它主线会不会改口」，不是「与决策有关」。收到这条提醒就回 `info-extraction.md` §3 重刷一遍分级。

**脚本查不了的**（必须人工做，且不能因为跑了脚本就跳过）：

- 口径是否可比、单位换算是否正确
- 证据是否真的支持结论
- 因果强度、范围词是否被夸大
- 图表类型是否匹配要表达的比较关系
- 标题是否真的是这一页的结论
- 执行摘要能否独立阅读

自动检查通过 ≠ 审计通过。**不得把缺失项改称「可选」然后宣称通过。**

## 6. 审计报告要素

1. **指标摘要**（表格）：A 级卡片总数 / 有去向数 / 覆盖率；B 级同；脚本错误数与警告数；冲突数；证据缺口数。
2. **覆盖审计表**：未使用的 A/B 级卡片逐条列出，含去向与原因。覆盖率为 100% 时也要写出表头并注明「无未安置卡片」。
3. **保真回查结果**：核对过的数字条数、失真条数与处置、无法回溯的数字清单。
4. **结构检查结果**：§2 的每项逐条给结论，不通过的要写修法。
5. **一致性检查结果**：内容稿 / 清洁版 / PPT 三方的差异清单。
6. **冲突清单**：冲突 ID、双方数值与口径、处置方式、是否已进稿件。
7. **证据缺口清单**：缺什么、影响哪个结论、补的方法。
8. **假设清单**：全部标为假设的项，及其影响。
9. **需要用户确认的事项**：具体选项 + 各自影响，不用开放性问题。
10. **本次未能修正的问题**：原因 + 建议处置。诚实列出，不隐藏。
