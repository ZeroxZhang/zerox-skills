# 架构决策

本套件的设计依据。改架构前先读本文，改动后同步更新本文。

## 1. 要解决的问题

咨询、商分、市调、行研、尽调、营销的报告产出不同，但生产链条同构：调研取证 → 建模分析 → 论证成线 → 表达成文 → 视觉呈现 → 交付质检。若按「报告类型」各写一套 skill，每类报告都要重复维护一份分析、论证与版式逻辑。因此按**能力**切分，报告类型只作为流水线层的装配入口。

## 2. 双层结构与职责边界

| 层 | 数量 | 职责 | 不做什么 |
|---|---|---|---|
| 路由 `zerox` | 1 | 意图识别、候选筛选、编排提示词生成 | 不执行业务逻辑；不自动调用子 skill |
| 能力层 | 6 | 价值链一段的方法与标准，可单独交付中间产物 | 不端到端产出报告；不指名兄弟 skill |
| 流水线层 | 5 | 一类报告的场景流程与章节骨架，装配能力层方法 | 不重复维护方法正文；不越过任务契约 |

## 3. 命名空间

套件 `zerox-skills` → 路由 `zerox` → 成员 `zerox-*`（镜像 dbskill 的 `dbskill` → `dbs` → `dbs-*`）。用户明确选择品牌前缀 `zerox-`，优先品牌一致性。

代价与缓解（已知并接受）：机器上另有 4 个套件外的 `zerox-*` 个人 skill——`zerox-swarm`（深度调研系统）、`zerox-mp-writting`（公众号写作）、`zerox-content-advisor`（社媒文案）、`zerox-workflow-conventions`（工作流规则）——共享前缀但不属本套件。因此：

- **成员资格以 `registry.md` 为准，不靠前缀判定**。路由发现候选只读注册表，不做前缀扫描。
- **易混 skill 的 description 必写边界句**（`zerox-research` 对 `zerox-swarm`、`zerox-writing` 对 `zerox-mp-writting`／`zerox-content-advisor`），近邻任务不误触发。
- 目录名 == frontmatter `name`，小写连字符，少于 64 字符。

## 4. 布局约束（来自安装机制）

`bridge-skill.sh` 的集合识别是 `find <dir> -mindepth 2 -maxdepth 2 -name SKILL.md`，只匹配 `<套件>/<成员>/SKILL.md` 一层。因此：

- 技能真源必须是套件目录的**直接一级子目录**，不得加 `skills/` 中间层；
- `templates/`、`docs/` 下不得出现名为 `SKILL.md` 的文件（脚手架用 `skill-skeleton.md`）；
- 整套接入一条命令：`bridge-skill.sh link <套件目录>`，成员不必逐个 link。

## 5. 路由契约

路由不执行业务逻辑，只做四件事：

1. **回收当前任务**：从会话中提取目标、材料、阶段、约束；最多问 1 个会改变分派的问题。
2. **发现候选**：读 `registry.md` 中状态为「已建」的成员（建路由时写脚本读取，并烘焙 `zerox/references/skill-names.txt` 作离线回退）。只认套件内成员。
3. **筛选**：候选阶段只比较 frontmatter，五准则——任务结果（是否直接产生交付或必要中间判断）、输入匹配（已有材料是否是它处理的输入）、阶段匹配（是否处理当前卡住的阶段）、边界匹配（边界句是否排除本任务）、可执行性（权限 / 文件 / 证据是否足够）。名称关键词只用于发现，不单独决定入选。
4. **产出编排提示词后停止**：给出可直接复制发送的 `/{skill}` 提示词。组合上限 1 主 + ≤2 辅，辅助角色仅三种：前置筛选（主结论前跑）、证据补充（主结论前补证据）、验收约束（定稿前查）。单一交付物，禁止多份报告拼接。

叶子 skill 禁止指名兄弟 skill（未来 CI 强制，规则先立），结尾只保留条件式路由提示。

## 6. 方法归属

**能力层 `references/` 是方法的唯一真源。** 流水线层跨目录只读引用 `../zerox-<能力>/references/*`，不复制正文、不调用兄弟流程。装配约束：套件按集合整链安装，不单装成员（否则只读引用会断链）。

## 7. 交付契约

任何分析 / 管线类任务动工前先写 `templates/task-contract.md` 实例并与用户对齐（受众、交付物、证据要求、验收标准、不做什么）。契约变更先于产出变更，验收以契约为准。这是把「做一份好报告」从形容词变成可检查行为的手段。

## 8. 增长原则

- **真实任务驱动**：skill 由反复出现的真实问题催生，不由规划清单催生。槽位只是占座，不是待办。
- **禁止空壳**：目录出现时 SKILL.md 必须已有可执行行为。
- **失败驱动修改**：改动必须能解释一类稳定失败。
- **入口保持轻**：SKILL.md ≤300 行，条件性细节进 `references/`，确定性重复操作进 `scripts/`。

## 9. 明确的非目标

- 不迁移、不修改、不依赖 `consulting_deck_skill` / `consulting-report-forge` / `consulting-report-skill`。
- 不调度套件外 skill（自研闭环）。
- 不为占位而建 skill、空目录、占位 README、changelog。
